## 2. 目标与非目标

### 2.1 目标
- 做一个真正“可以玩”的 1vN 格战棋 PVE 战斗，而不是调试用试验台。
- 交互质感对标 BG3：移动高亮、命中率预览、动作栏、反应弹窗、骰子结算演出。
- 规则结算完全自动化且确定性强，所有掷骰可追溯、可导出、可回放。
- 把“技能内容”和“规则引擎”彻底解耦：内容由结构化卡片驱动，不把规则写死在 UI。
- 为后续 PVP、DM 结算台、其他职业扩展保留干净的接口。

### 2.2 非目标（v1 明确不做）
- 不做 3D / 2.5D 画面。
- 不做潜行、隐形、视野/战争迷雾。
- 不做多角色小队、NPC 队友。
- 不做联机。
- 不做高度攀爬、飞行、真实 Z 轴寻路。
- 不做 DM 手动干预全功能（DM 结算台独立版本再做）。
- 不做除游荡者 v1 技能范围之外的 13 个职业。

## 3. 产品模式

### 3.1 PVE 模式（v1）
1. 从角色面板选择一个已有角色存档，生成只读战斗快照。
2. 选择遭遇（1 名玩家角色 vs N 个怪物）。
3. 玩家掷先攻 D20 + 敏捷调整；怪物使用固定先攻值。
4. 布阵：玩家选择初始格与朝向。
5. 进入标准回合循环，直至胜利或失败。
6. 结算界面展示战斗日志，可导出。

### 3.2 PVP 模式（后续）
- 第一版 PVP：同机热座，两张角色卡轮流操作，轮次间加“移交挡板”。
- 网络联机：在热座版稳定后单独设计房间/同步/断线重连，不纳入 v1。

### 3.3 DM 结算台（后续）
- 目标不是自动游戏，而是记录真实跑团战斗。
- 功能：手动建单位、手动/自动掷骰、快速伤害治疗、状态管理、先攻队列、反应次数、战斗日志导出。
- DM 结算台与 PVE 共用引擎核心，但 UI 和权限不同。

## 4. 核心概念与术语

| 术语 | 含义 |
|---|---|
| 格 | 棋盘最小单位，1 格 = 1 米 |
| 朝向 | 单位面向的 8 方向之一：N/NE/E/SE/S/SW/W/NW |
| 背后 | 单位朝向反方向的那一格 |
| 相邻 | 周围 8 格，包括斜角 |
| 水平距离 | 正交 1、斜角 2 的格子距离 |
| 实际距离 | 水平距离 + 竖直高度差（米） |
| 基础移动 | 消耗附赠动作获得的移动预算，步数 = 基础移动力 |
| 全速移动 | 消耗主要动作获得的移动预算，步数 = 基础移动力 × 2，与基础移动/跳跃互斥 |
| 反应动作 | 仅能在他人回合使用的动作，整场至多 3 次 |
| 战斗快照 | 从角色面板存档读取出的只读战斗用角色卡 |
| 能力卡 | 可被引擎执行的结构化技能/天赋/攻击数据 |
| 状态卡 | 异常状态的层数、触发时机、修正、解除条件 |
| 模板 AI | 怪物卡上声明的行为优先级规则 |

## 5. 棋盘与空间

### 5.1 格子与朝向
- 棋盘为正方形网格，坐标 `(x, y)`，1 格 = 1 米。
- 朝向固定为 8 个枚举值：
  `N, NE, E, SE, S, SW, W, NW`。
- 朝向变化规则：
  1. 布阵时玩家显式选择初始朝向。
  2. 普通移动完成后，朝向自动等于最后一步的方向。
  3. 没有移动的回合，朝向保持不变。
  4. 施放有方向性的技能时，施法者先转向“技能指向目标的方向”：
     - 若目标相对方向接近四个正方向，则取对应正方向；
     - 否则归一到最近的四个斜方向；
     - 不存在任意角度朝向。
  5. 除上述规则外，v1 不提供独立“转身动作”。

### 5.2b 扇形（锥形）范围模板

- 从施法者格出发，沿 8 方向之一展开的倒三角形。
- 正方向第 r 层宽度 = `2r - 1`，以方向轴为中心。
- 斜方向第 r 层 = r 格：方向 `(dx,dy)` 时取 `(dx*k, dy*(r+1-k))`，`k=1..r`。
- 2 环正方向 = 1+3 格；3 环正方向 = 1+3+5 格。
- 示例与详细公式见 `snode-combat/docs/rule-decisions.md` 第 6 章。

### 5.2 距离函数
引擎必须实现并只允许使用以下三个函数：

```
// 水平移动/射程距离：正交 1，斜角 2
gridDistance(a, b) = |ax - bx| + |ay - by|

// 相邻判定：周围 8 格都算相邻
isAdjacent(a, b) = max(|ax - bx|, |ay - by|) <= 1

// 实际距离：水平距离 + 高度差
combatDistance(a, b) = gridDistance(a, b) + abs(a.z - b.z)
```

**重要推论（必须写死）：**
- 射程 2 米：可覆盖正方向 2 格；斜方向只能覆盖相邻 1 格，斜方向第 2 格需要 4 米射程。
- 射程为“近战/触及”时使用 `isAdjacent`，因此斜角相邻虽然水平距离为 2，仍可命中。
- 移动、跳跃、远程射程使用 `gridDistance` 或 `combatDistance`。
- 借机威胁范围使用 `isAdjacent`。
- 不得出现 UI 高亮与引擎判定使用不同距离定义的情况。

### 5.3 高度与距离
- 单位和物件可以有整数 `z`（单位：米）。
- 实际距离 = `gridDistance + |z1 - z2|`。
- 近战/触及相邻要求：`isAdjacent` 为真且 `|z1 - z2| <= 1`。
- 高度差 ≥ 2 时近战/触及不可用，远程仍按实际距离判断。

### 5.4 v1 地形范围
v1 地形只做以下类型：
- `floor`：普通平地。
- `blocked`：不可通行墙体。
- `cover`：掩体，按斯诺德规则处理攻击劣势/瞄准要求。
- `danger`：危险格，后续接入具体效果。

v1 不制作可攀爬高台、坑洞坠落、飞行和真实 Z 轴寻路。

## 6. 单位与角色卡

### 6.1 玩家单位
- 来源：角色面板存档的只读快照。
- 快照至少包含：8 属性、HP/FP 最大值、AC、基础移动力、体型、朝向、装备、熟练项、技能列表、种族/职业被动。
- 战斗中的 HP/FP/状态/消耗次数等属于**战斗实例数据**，与角色卡快照分离。
- 战斗结果不写回角色面板。

### 6.2 怪物单位
- 来源：结构化怪物卡。
- 字段至少包含：属性、HP/FP、AC、速度、体型、先攻、武器、技能列表、AI 规则、掉落/奖励。

### 6.3 v1 体型
- v1 先只实现 1×1 格单位；体型字段保留，但 2×2 等占位规则后续再做。
- 此条为 v1 范围决定，不修改规则正文。

## 7. 回合结构

### 7.1 战斗阶段
```
初始化战斗
 → 加载玩家快照与怪物卡
 → 生成棋盘与初始站位
 → 掷先攻 / 读取固定先攻
 → 建立先攻队列
 → 玩家布阵（选格 + 选朝向）

回合循环：
 → 回合开始阶段
    - 持续状态 tick（灼烧/中毒/流血等）
    - 死亡裁决（若玩家 HP ≤ 0）
 → 行动阶段
    - 玩家/怪物可执行合法动作
    - 移动、主要动作、附赠动作
    - 反应窗口（他人回合触发）
 → 结束回合
    - 持续时长递减
    - 结束类效果结算
    - 移动预算清零、动作预算重置
 → 下一单位 / 新一轮
 → 胜负判定
```

### 7.2 先攻
- 玩家：`D20 + 敏捷调整值`。
- 怪物：怪物卡上的固定先攻值。
- 排序：降序。
- 同值处理：规则正文未写明。**待裁决**，草案推荐“玩家优先；多个怪物同值按遭遇卡中的出场顺序”。在拍板前不实现自动排序的隐藏偏好，只做显式规则。

### 7.3 轮次
- 先攻队列从头走到尾再回绕时，轮次 +1。

## 8. 动作经济

100% 按 `help.html` 战斗规则执行：

### 8.1 每回合预算
- 主要动作：1 个。
- 附赠动作：1 个。
- 反应动作：整场战斗至多 3 次，且只能在他人回合使用。

### 8.2 主要动作
1. 使用武器/道具攻击
2. 施展需要主要动作的技能
3. 全速移动（不可与基础移动/跳跃共存）
4. 稳定濒死角色
5. 投掷物品
6. 将主要动作转为附赠
7. 回避
8. 精密互动

### 8.3 附赠动作
1. 施展需附赠动作的技能
2. 基础移动
3. 跳远/跳高
4. 抓取/放下物件
5. 切换武器/防具
6. 说较长的话
7. 主动属性/熟练项检定
8. 瞄准部位
9. 扑灭火焰
10. 手下留情
11. 简易交互

### 8.4 技能施展时间映射
- `1动作` → 主要动作。
- `附赠动作` → 附赠动作。
- `反应动作` → 反应动作，受整场 3 次上限约束。
- `0动作` → 附赠动作。
- 短休/长休类能力不进入 v1 战斗。
- 主要动作与附赠动作的先后顺序由玩家自行决定。

### 8.5 BG3 化表达
- 底部动作栏用“点亮/熄灭”显示主要动作与附赠动作是否可用。
- 移动是“动作”而非免费资源，UI 必须让玩家清楚看到：基础移动会点亮/消耗附赠动作，全速移动会点亮/消耗主要动作。

## 9. 移动系统

### 9.1 基础移动
- 消耗：1 个附赠动作。
- 预算：基础移动力（米 = 格数）。
- 基础移动力受修正链影响：力竭一层减半、腿部断肢减半、减速/麻痹步数减半（向下取整）、技能/天赋/专长增减。

### 9.2 全速移动
- 消耗：1 个主要动作。
- 预算：基础移动力 × 2。
- 与基础移动、跳远/跳高同回合互斥。

### 9.3 分段移动与 BG3 式自动升级
- 基础移动换取的是“回合内移动预算”，可分段使用。
- 若累计路径超过基础移动力：
  - 自动升级为全速移动；
  - 返还已消耗的附赠动作；
  - 最终只消耗 1 个主要动作；
  - 预算变为 `2 × 基础移动力 - 已用步数`。
- UI 必须实时显示：当前模式、剩余步数、升级提示。

### 9.4 斜向移动
- 每斜向一步消耗 2 步，8 方向可走。

### 9.5 路径与碰撞
- 不可进入障碍格或其他单位占用格。
- 途经或离开敌方 `isAdjacent` 威胁范围时，触发借机攻击机会。
- 迅捷、击退等按规则不触发借机。

### 9.6 跳跃
- 距离 = 力量或敏捷调整值 + 跳跃熟练度 + 1（格）。
- 仅沿 8 个直线方向。
- 途经他人时，对方可借机。
- 全速移动后不可跳跃。

### 9.7 高度
- v1 全部按平地移动处理；墙体 `blocked` 不可通行。
- 飞行、跃迁、攀爬不进入 v1。

## 10. 技能结算管线

所有技能必须走同一条管线：

```
选择技能
 → 前置校验
    - 动作类型可用
    - FP / 使用次数 / 资源足够
    - 射程、目标规则合法
    - 关键词限制（状态禁止项）
    - 第一行动 / 引导 / 专注等限制
 → 施法者转向目标方向（见 5.1）
 → 范围与合法目标高亮
 → 命中率 / 豁免难度预览
 → 执行掷骰（种子化 RNG，逐骰记录）
 → 效果序列逐条结算
 → 反应窗口检查
 → 战斗日志写入（含完整加值与骰值明细）
```

### 10.1 铁律
- 自然语言描述只用于 UI 展示。
- 引擎只执行能力卡中的结构化效果序列。
- 无法结构化的效果**不得**进入自动战斗，在 v1 中标记“未开放”，留给后续 DM 结算台手动处理。
- UI 不得绕过引擎直接修改 HP/FP/状态。

## 11. 攻击、命中与伤害

- 公式以 `snode-combat/docs/rule-decisions.md` 第 1~4 章为权威裁决。
- 近战/非奇械远程武器命中：`D20 + 武器所需关键属性调整 + 武器熟练项点数 + 攻击命中加成 + 其他加成`。
- 奇械远程武器命中：`D20 + 枪械武器熟练项点数 + 敏捷属性调整值 + 攻击命中加成 + 其他加成`。
- 施法攻击命中：`D20 + 技能来源职业关键属性调整 + 法术命中加成 + 其他加成`。
- 无武器熟练项时攻击劣势；熟练项每点 +1。
- 武器伤害：非奇械 = 骰 + 武器关键属性调整；奇械 = 骰，无属性调整。
- 暴击：D20 20 必中，结算前伤害翻倍；结算后加成不吃暴击。
- 大失败：D20 1 未命中；攻击范围内有队友则对队友重检（不再大失败），否则自身击倒。
- 远程攻击相邻有敌时劣势（按斯诺德规则）。
- 优势/劣势/极大优势/极大劣势/绝对优势/绝对劣势按规则掷 2~4 骰取高/低。
- 伤害再走抗性/护盾/临时生命等修正；全部写入日志。

---

## 12. 状态系统

- 每个状态必须是一张结构化“状态卡”。
- 状态卡字段：层数、叠加方式、触发时机、属性修正、行动限制、自动解除条件、来源。
- v1 首批状态（预计 15~20 个）以游荡者技能和首批怪物技能覆盖为准。
- 状态触发钩子至少包括：
  `onTurnStart / onTurnEnd / onHit / onDamaged / onMove / onAttack / onDeath / onRoundStart / onRoundEnd`。
- 状态持续时长统一在回合/轮次边界结算。

## 13. 死亡与胜负

### 13.1 玩家
- HP ≤ 0：进入死亡裁决。
- 每个自身回合开始时掷 D20 死亡裁决骰：
  - 低于 10 → 1 个死亡标记；
  - 不小于 10 → 1 个生命标记；
  - 3 个生命标记 → 获得 1 层力竭，HP 回调至 1，解除失能；
  - 3 个死亡标记 → 死亡。
- 治疗使 HP ≥ 1 时中止死亡裁决，清除生命标记，死亡标记保留至本场战斗结束。
- 死亡裁决骰不可重掷、不可加减值。

### 13.2 怪物
- HP ≤ 0：直接退场（v1 范围决定）。

### 13.3 胜负
- 所有怪物退场 → 玩家胜利。
- 玩家死亡/投降 → 失败。

## 14. 怪物 AI

- v1 使用模板 AI：怪物卡声明 2~3 条优先级规则。
- 规则示例：
  1. 若范围内有敌方，优先使用可用技能；
  2. 否则向最近目标移动；
  3. 移动后若能攻击，执行基础攻击。
- AI 必须通过引擎合法动作接口执行，不得直接改数值。
- DM 结算台完成后再增加手动接管。

## 15. 数据模型（战斗卡片 schema）

完整 schema 已落盘为 `snode-combat/docs/data-schema.md`（v0.1 草案）。

草案分五类：
- `unit`：单位卡。
- `ability`：能力卡。
- `status`：状态卡。
- `monster`：怪物卡。
- `encounter`：遭遇卡（棋盘、地形、怪物、奖励）。

设计原则：
- 全部 JSON/TS 类型定义；
- 展示文本与执行效果分离；
- 效果表达式可序列化、可解释、可测试；
- 不引入 HTML 字符串进核心数据。

## 16. UI / UX 规范（BG3 式外壳）

### 16.1 画面结构
```
┌──────────────────────────────────────┐
│ 2D 棋盘（PixiJS 渲染）                │
│ 移动高亮 / 攻击范围 / 路径 / 棋子 HUD   │
├──────────┬───────────────────────────┤
│ 先攻队列  │ 选中单位信息 / 技能详情       │
│          │ 骰子结算层 / 战斗日志        │
├──────────┴───────────────────────────┤
│ BG3 式底部动作栏：                    │
│ 移动 / 主要动作 / 附赠动作 / 道具 / 结束  │
└──────────────────────────────────────┘
```

### 16.2 必须有的交互
- 点击棋子：选中并显示详情。
- 选中后：高亮移动范围、剩余步数。
- 选择技能：高亮合法范围与目标，显示命中率或豁免 DC。
- 反应窗口：弹窗暂停，后发先置。
- 骰子结算：D20 滚动 + 加值明细。
- **掷骰演出为硬性需求，不可省略**：释放技能时，在“命中结果”和“伤害结果”揭晓前，都必须先播放对应的掷骰动画（命中 D20、伤害骰/豁免骰等），动画与真实骰值一一对应。
- 伤害/治疗/状态：数字飘字 + 状态图标。
- 敌人信息默认隐藏具体数值，只显示受伤程度与状态图标（PVE 玩家视角）。
- 日志可展开查看每一掷的明细。

## 17. 演出与反馈

- 2D 棋子 + 粒子/闪光/飘字特效。
- 演出不得改变结算结果；先结算后播放。
- 可跳过/加速演出。
- 骰子事件与引擎日志一一对应。

### 17.1 掷骰交互归属（硬性规则）

- **玩家主动释放的能力**：攻击命中、伤害骰、附加伤害骰、层数骰（如中毒/流血的 1D3）等，尽量交由玩家点击掷骰。
- **玩家自身承受异常状态需要过豁免**：由玩家亲自掷豁免骰。
- **怪物过豁免/怪物自己的攻击与伤害**：不交给玩家，播放简短掷骰动画并展示结果（BG3 式）。
- **1D3 层数骰**：玩家主动能力造成的中毒/流血层数，以及玩家自身获得的中毒/流血层数，均由玩家掷骰。骰具为 D6：1/2=1 层，3/4=2 层，5/6=3 层。
- 怪物之间的结算（若有）一律自动动画。
- 引擎只负责生成“待掷骰请求”与归属（`player` / `auto`），UI 按归属决定是否等待玩家点击；规则结算不得依赖动画，但玩家掷骰请求未完成时对应结算步骤处于暂停状态。

## 18. 对局保存、导出与回放

- v1 支持对局中途保存到本地（独立战斗存储，不写角色面板）。
- 支持恢复对局。
- 支持导出：
  - 文本战斗日志；
  - JSON 完整回放文件；
  - 战斗记录摘要。
- 所有掷骰记录包含种子与序列，保证回放一致。

## 19. 技术架构

- 核心：TypeScript，纯逻辑，无 DOM，无渲染依赖。
- 渲染：PixiJS。
- UI：HTML/DOM 覆盖层。
- 构建：Vite。
- 测试：Vitest（核心）+ Playwright（E2E）。
- 输出：静态文件，Electron 与网页版共同使用。
- 现有角色面板与职业页代码不耦合、不改动。

分层规则：
- `core` 不得 import `render` / `ui`。
- `ui` 不得直接修改战斗状态，只能调用 `core` 命令接口。
- `render` 只读状态 + 特效，不参与规则判定。

## 23. 测试策略

- 核心规则：单元测试，一条规则至少一个用例。

- 状态：触发钩子、层数、到期、解除。
- 掷骰：种子确定性、优势/劣势骰数、回放一致。
- AI：怪物行为优先级测试。
- UI：Playwright E2E，覆盖完整 PVE 一场战斗。
- 导出：日志与回放文件可解析、可复现。
