# v1.0.8093

发布日期：2026-11-01。

修复「更新一直下载、却从不安装」。

## 一、问题复现（真机日志）

用户机器上 1.0.8087 连续三次出现同一循环：

```
portable-check-start → portable-manifest(1.0.8092) → portable-download-start
→ portable-downloaded          ← 到此为止
→ （用户关闭应用）updater-installer-missing reason=quit
```

三处缺陷：

| # | 位置 | 问题 |
|---|---|---|
| 1 | `app.on('will-quit')` | 只有安装器分支；便携模式退出时走 `launchInstallerDelayed`，没有安装器文件 → 什么都不装 |
| 2 | `startPortableDownload` 完成处 | 自动检查只下载不安装，必须用户点按钮 |
| 3 | `启动台.html updateAction()` | 安装要过 `window.confirm`；且文案写「重启后生效」，引导用户直接退出（正好落入缺陷 1） |

## 二、修复

### 1. 便携模式：退出即装

`will-quit` 增加便携分支：只要已有下载好的更新，退出时直接 spawn 覆盖命令（`skipExit` 避免重复 `app.exit`），不再误走安装器分支。

### 2. 断点续装

下载完成即写 `%APPDATA%\snowd-skill-tree\pending-update.json`（版本 / zip 路径 / sha512 / 大小）。启动时读取：

- zip 存在且大小一致 → 直接视为「已下载」，**不再重下 190 MB**，退出时自动安装；
- 文件丢失或大小不符 → 清理断点并重新检查。

apply 成功（已 spawn）后删除断点文件。

### 3. UI 与文案

- 去掉 `window.confirm`：点「立即重启安装」直接调用 `installUpdate()`（按钮本身已是明确意图）；
- 下载完成文案改为「更新已下载完成（v…）；**关闭应用时会自动安装**」；
- 卡片提示同步改为「关闭应用时自动安装」。

### 4. 诊断补全

新增日志：`portable-apply-on-quit`、`portable-apply-skip`（no-pending / no-zip）、`pending-update-saved`、`pending-update-restored`、`portable-update-already-downloaded`、`updater-install-click`。
