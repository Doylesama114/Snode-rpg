# v1.0.8076

发布日期：2026-10-27。

修复 1.0.8074 / 1.0.8075 引入的**启动崩溃**，并让延迟安装真正可用。

## 一、线上问题

1.0.8075 下载完成后，应用在拉起安装器时抛 `ReferenceError`，随后弹出「斯诺德跑团发生启动异常」：

```
04:32:35  updater-install-attempt  version=1.0.8075
04:32:35  main-fatal  code=ERROR name=ReferenceError site=main.js:383:42
```

## 二、三个缺陷

| # | 缺陷 | 后果 |
|---|---|---|
| 1 | 命令拼接里残留 Python 写法 `chr(34)` | 运行时 ReferenceError → 启动异常弹窗，安装永远不执行 |
| 2 | `spawn('cmd.exe', ['/c', cmd])` 缺 `windowsVerbatimArguments` | Node 会把整串参数加引号，`ping … & "安装包" …` 的 `&` 不再是命令分隔符，安装器不会运行 |
| 3 | `app.getPath('localAppData')` 不是合法的 Electron 路径名 | TEMP 硬化与更新缓存清理静默失效（日志 `updater-cache-prune-failed`） |

## 三、修复

- `var q = String.fromCharCode(34);` 拼接引号，彻底去掉 `chr(34)`
- spawn 增加 `windowsVerbatimArguments: true`
- 路径基址改用 `process.env.LOCALAPPDATA`（Windows 必存在）

## 四、这次是真的执行验证过的

新增校验不只检查代码文本，而是**真的跑一遍命令**：

```js
// verify_update_flow_e2e.mjs ⑧
提取 main.js 里的 q + cmd 两行 → 用带空格的假安装包路径 → spawnSync 真实执行 → 断言标记文件生成
```

结果：**53P 0F**（含「延迟安装命令真实执行（含空格路径）」）。另外新增两条静态断言，防止 `chr(` 与 `getPath('localAppData')` 再次混入。

## 五、安装说明

1.0.8074 / 1.0.8075 都带这个崩溃，**无法自更新**，请手动安装本版一次；从 1.0.8076 起，下次自动更新才会走正确的延迟安装路径。
