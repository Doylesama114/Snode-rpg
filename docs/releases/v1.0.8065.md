# v1.0.8065

发布日期：2026-10-22。

发布链路修复：更新器不再因 GitHub 尚未发布而静默停在旧版；Release 创建竞态容错；CI 增加发布后资产自检。**本版不含 macOS 安装包。**

## 一、为什么有这一版

v1.0.8064 的代码与数据都已就位（OSS 镜像上的安装包、移动端包、更新清单全部可用），但它的 GitHub Release 在生成后消失，`/releases/latest` 仍指向 v1.0.8063。桌面端自动更新检查优先读这个接口，于是老用户会被告知「已是最新」，实际停在旧版。这一版既补一个干净的新版本号（全新 tag，不涉及任何 tag 删除），也把暴露出来的链路缺陷修掉。

## 二、更新器：按版本比较，源落后就换源

- `electron-app/main.js` 新增 `compareVersion()`；`fetchLatestTag` 拿到的版本与当前版本比较后分流：**更新 → 立即使用**；**同版 → 记为兜底并继续询问下一个源**；**落后 → 仅作兜底**。
- 全部源问完仍无更新时，用兜底源走 autoUpdater 的正常流程（显示「已是最新」）：不再把「源落后」当成「没有更新」，也不再因此报错。
- 自动检查（启动时、启动后 90 秒补检）的源由 `['github']` 改为 `['github','oss']`：GitHub 没有目标版本时，镜像依然能给出正确版本；手动检查原本就是 `['oss','github']`。
- 「单源 GitHub 失败才回退镜像」不再是唯一退路，但仍保留在 autoUpdater 自身报错时兜底。

## 三、Release 创建竞态与 CI 自检

- `release.yml` 建 Release 的步骤增加「已经存在」容错：`gh release create` 失败后重新 `gh release view`，能查到即视为 macOS 工作流并发创建成功，继续上传，不再直接判红。
- 新增 `Verify published release` 步骤：Release 不存在、缺 `Snode-RPG-Setup-<版本>.exe`、缺 `latest.yml`、或**正文短于 200 字符**（发布说明没写进去，Release 只是空壳）都判失败。把「CI 绿着但没发出去」从人工发现变成 CI 自己红。
- `build-mac.yml` 的发布步骤支持 `workflow_dispatch` 补发：条件补上 `inputs.ref` 为 tag 的情形，`RELEASE_TAG` 从 `inputs.ref` 解析。此前官方说明里的「手动补发」对 DMG 实际无效（`github.ref` 是分支，步骤被跳过）。

## 四、macOS

- **本版不提供 Mac 安装包**（mac 延后，随下一版一起发）。
- 因此 `mac-platform.js` 在「有新版本但没有本架构安装包」时改为中性态（`status: 'uptodate'` + `platformMissing: true`），不再每次启动弹红色错误。
- `checkForMacUpdates()` 在 GitHub 不可达时会读镜像 `latest.json`：镜像已有更高版本时，提示里直接给出发布页地址，而不是只丢一句网络错误。macOS 安装包只托管在 GitHub、镜像无法直接下载，这一点没有改变。

## 五、规则与验收

- `工作规则.md` §1 新增两条硬规则：**禁止删除已推送的 `v*` tag**（删 tag 会异步连带删除其 Release，重新推 tag 后仍可能被再次清掉）；**发布验收以资产为准**（`/releases/tags/<tag>` = 200、资产数达标、exe 与 latest.yml 一致、正文 ≥ 1500 字、`/releases/latest` 指向新版本）。
- `scripts/tests/mac-platform.test.cjs` 新增「有更高版本但没有 Mac 安装包 → 中性态」用例；原「Windows 资产不能给 Mac 用户」断言同步改为中性态。

## 六、验证

- `node --check electron-app/main.js` / `mac-platform.js` 通过。
- `node --test scripts/tests/mac-platform.test.cjs`：6 项通过（第 7 项依赖 `electron-app/node_modules` 的 app-builder-lib，属本机环境缺失，CI 上正常）。
- `node verify_all.mjs`：与基线一致（清 57/57、889 断言通过；4 项 `Cannot find module .../electron-app/node_modules/electron` 为环境问题）。
- 发版后按 §五 的资产清单核验，并核对 OSS `latest.json` / `latest.yml` / `mobile/version.json` = 1.0.8065。

## 七、已知遗留

- v1.0.8064 的 GitHub Release **不追补**：追补需要动 tag，而删 tag 正是它的死因；其 OSS 链路完整可用，桌面端与移动端都能正常更新。
- macOS 安装包下一次随版本发布，届时确认两个 DMG 出现在 Release 资产中。
