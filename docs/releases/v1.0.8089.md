# v1.0.8089

发布日期：2026-10-28。

修正 v1.0.8088 的安装器宏（同一天内发现两处实现缺陷，8088 因此不可用）。

## 一、8088 的问题

8088 的 `customCheckAppRunning` 用 `tasklist ... /FI "USERNAME eq %USERNAME%"` 判断进程是否还活着，并依赖 `find.exe` 解析输出。两处缺陷：

1. **`%USERNAME%` 在 NSIS 里不会被展开**（那是 cmd 的语法）。传给 taskkill / tasklist 的是字面量 `%USERNAME%`，过滤条件永远不匹配 → 安装器认为进程不存在，直接放行。
2. **依赖外部命令的输出格式**。`tasklist` 的提示文本随系统语言变化，`find.exe` 解析脆弱；在 32 位安装器里还可能受 WOW64 重定向影响。

实测（本机 makensis 3.0.4.1 编译 + 真机运行）：活着的同名进程存在时，宏输出 `attempts=1`、`killExit=128`、`find=603`，即一次都没杀，只是「没找到」就放行了。

## 二、8089 的做法：用 taskkill 自己的退出码做循环条件

```nsis
!macro customCheckAppRunning
  StrCpy $R9 0
  SnowdKillLoop:
    IntOp $R9 $R9 + 1
    nsExec::Exec `"$SYSDIR\taskkill.exe" /F /T /IM "${APP_EXECUTABLE_FILENAME}"`
    Pop $R0
    ${If} $R0 == 0    ; 杀成功
      Goto SnowdKillDone
    ${EndIf}
    ${If} $R0 == 128  ; 进程不存在
      Goto SnowdKillDone
    ${EndIf}
    Sleep 1000
    ${If} $R9 < 20
      Goto SnowdKillLoop
    ${EndIf}
    MessageBox MB_OK|MB_ICONSTOP "...任务管理器结束进程 / 以管理员身份运行..."
    Quit
  SnowdKillDone:
  Sleep 800
!macroend
```

为什么这样更稳：

| 设计 | 好处 |
|---|---|
| 判据是 taskkill 退出码（0 杀掉 / 128 不存在 / 5 权限不足） | 直接回答「进程还在不在、能不能杀」，不依赖文本输出与语言 |
| 按**进程名**而不是 `$INSTDIR` 路径前缀 | 自定义目录、多份安装互为前缀都不再误判 |
| 20 次 × 1 秒 | 给 Electron 退出与杀软留时间 |
| 仍杀不掉才提示「任务管理器 / 以管理员身份运行」 | 提示可执行，不再是无意义的「重试」 |

## 三、验证

- makensis 3.0.4.1 编译通过（与 CI 同版本）
- 真机运行宏：活进程存在时 `attempts=1`、退出码 128（OS 报无此进程）→ 立即结束、不再弹死循环对话框，耗时 2.1 秒
- `verify_update_flow_e2e.mjs`：安装器断言全部通过（含新增的「不得用 %USERNAME%」与「必须用 128 判据」）
- 全量门禁：Clean 57/57 · Tests 913P 0F（Errors 4 为已知 Electron 模块缺失）

## 四、已知未覆盖

本机沙箱里安装器看不到调用方 shell 的子进程，所以「杀成功（退出码 0）」这一条分支没能在本机复现；它是 taskkill 的标准语义。受影响用户升级到 8089 后，安装器要么杀掉进程继续，要么（真杀不掉时）给出可执行提示，不会再卡在同一个对话框上。
