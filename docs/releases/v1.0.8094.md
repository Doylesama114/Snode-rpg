# v1.0.8094

发布日期：2026-11-01。

修复「旧用户更新后应用打不开 / 装不上」——安装器不再被已经消失的旧目录拖死。

## 一、真机定位到的完整链路

从用户机器上取到的证据：

```
注册表：DisplayName=斯诺德跑团 1.0.8090
        InstallLocation=（空）
        UninstallString="D:\SnodeRPG\Uninstall 斯诺德跑团.exe" /currentuser
实际：  D:\SnodeRPG exists=False      ← 安装目录已经不存在
        %LOCALAPPDATA%\Programs\... 也没有
```

安装器日志 `setup-1.0.8093.log`：

```
installdir: D:\SnodeRPG
kill-attempt-1 exit=128          （应用没在跑）
check-app: killed or absent
（到此中断）
```

结合源码还原出的链路：

1. `uninstallOldVersion` 把**旧卸载器**复制到临时目录并执行（`_?=D:\SnodeRPG`） |
2. 旧卸载器把目录里的文件**连同目录一起删掉**，然后因为它自己就在那个目录里运行、删不掉自己而返回非零 |
3. `uninstallOldVersion` 看到非零 → **最多重试 5 次**，每次仍失败 → 弹 `$(appCannotBeClosed)`（就是那句中文「无法关闭，请手动关闭后点重试」） |
4. 用户点取消 → 我们的迁移桥忽略失败继续 |
5. 此时 `$INSTDIR` 已经被删 → 安装器写 `Uninstall 斯诺德跑团.exe` 失败 → 「不能打开要写入的文件」 |
6. 安装中止 → 目录没了、注册表残留 → **应用打不开** |

这也解释了「很多旧版打不开」：他们都在同一条路径上。

## 二、修复（全部在 `installer.nsh`）

### 1. 目标目录体检与回退

`customInit` 里（此时 `$INSTDIR` 已由 `initMultiUser` 解析完毕）：

- `$INSTDIR` 里**没有主程序** → 判定为「目录已失效」：
  - 清掉注册表里的 `InstallLocation`
  - 改用默认目录 `%LOCALAPPDATA%\Programs\<产品名>`
- 再对目标目录做**写探测**（`FileOpen ... w`），写不进去（ACL/只读/安全软件）→ 同样退到默认目录

### 2. 不再调用旧卸载器

清空 `UninstallString` / `QuietUninstallString` → `uninstallOldVersion` 读到空值直接 `Return`：

- 不再有 5 次重试的中文「无法关闭」弹窗
- **不再出现「旧卸载器把目录删掉才失败」**

### 3. 清掉残留卸载器

`taskkill /F /T /IM "Uninstall 斯诺德跑团.exe"` + 清只读属性 + `Delete`，避免新卸载器写不进去。

### 4. 安装后校验

`customInstall`：`exe` 与 `resources\app.asar` 必须存在；缺失则直接提示「请改用便携 zip」并给出日志路径，不再「装失败却像成功」。
