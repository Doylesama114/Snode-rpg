# v1.0.8088

发布日期：2026-10-28。

修复更新时卡在「斯诺德跑团 无法关闭。请手动关闭它，然后单击重试以继续。」

## 一、现象与成因

旧版本（≤1.0.8082）在应用内点「检查更新」后，会下载 Setup 并以 `--updated /S` 运行。安装器启动时执行 electron-builder 的 `_CHECK_APP_RUNNING`：

```nsis
!insertmacro FIND_PROCESS "..." $R0        ; 判据：进程路径 StartsWith($INSTDIR)
!insertmacro KILL_PROCESS "..." 1          ; Stop-Process -Force（同样按 $INSTDIR 过滤）
${if} $R1 > 1
  MessageBox ... "$(appCannotBeClosed)" /SD IDCANCEL IDRETRY loop
```

这套逻辑有三个结构性缺陷：

| # | 缺陷 | 后果 |
|---|---|---|
| 1 | 判据是**进程路径前缀**，不是进程名 | 应用装在自定义目录、或多份安装互为路径前缀时匹配错乱 |
| 2 | `Get-CimInstance` 枚举**全机**进程，但 `Stop-Process` 只能杀同用户/同权限的 | 跨用户或提权运行的应用永远杀不掉 → FIND 永远为真 |
| 3 | 重试窗口只有 1s + 2s | Electron 多进程 + 杀软拖慢时来不及退出；点「重试」回到同一个短窗口，永远失败 |

## 二、修复：接管 `customCheckAppRunning`

`electron-app/installer.nsh` 现在提供自己的实现（electron-builder 官方扩展点）：

```nsis
!macro customCheckAppRunning
  ; 先温和，再强制；/T 连子进程；按进程名而不是路径
  nsExec::Exec `...\taskkill.exe /IM "${APP_EXECUTABLE_FILENAME}" /T /FI "USERNAME eq %USERNAME%"`
  Sleep 1500
  SnowdKillLoop:
    nsExec::Exec `...\taskkill.exe /F /T /IM "${APP_EXECUTABLE_FILENAME}" /FI "USERNAME eq %USERNAME%"`
    Sleep 1000
    nsExec::Exec `...\tasklist ... | ...\find.exe /I "${APP_EXECUTABLE_FILENAME}"`
    ... 最多重试 20 次 ...
    MessageBox "请用任务管理器结束…或以管理员身份运行安装包"
!macroend
```

对应关系：缺陷 1 → 改成按进程名；缺陷 2 → `/FI "USERNAME eq %USERNAME%"` 只处理当前用户，杀不掉时明确提示提权；缺陷 3 → 20 次 × 1 秒。

## 三、顺带移除 `preInit`

早期为「把安装器固定到 D:\SnodeRPG」加的 `preInit` 已删除：它会让安装器的 `$INSTDIR` 与用户真实安装目录错位，是另一类更新失败的来源。

便携版（≥1.0.8083）的更新完全不经过安装器，本次改动只影响用 Setup 安装/迁移的场景。

## 四、验证

- `verify_update_flow_e2e.mjs`：**86P 0F**（新增 6 条安装器断言：自定义宏存在、`taskkill /F /T`、20 次重试、可执行提示、无 `preInit`、保留迁移桥）
- 真机验证：用同名假进程模拟「应用运行中」，运行 8088 Setup `--updated /S`，安装器 20 秒内强杀成功并完成安装（见发布记录）

## 五、受影响的用户

卡住的用户可以：
1. 任务管理器结束所有 `斯诺德跑团.exe` 后重跑安装包；
2. 或直接下载 `Snode-RPG-1.0.8088-win-x64.zip` 解压使用便携版（推荐，之后更新全自动）；
3. 或右键安装包「以管理员身份运行」。
