# v1.0.8100

发布日期：2026-11-04。

修复「更新时弹出 `ping 127.0.0.1 -n 12` 黑窗」。

## 一、现象

用户点更新后，屏幕中央会闪出一个标题为 `ping 127.0.0.1 -n 12` 的控制台窗口（有时停留数秒），随后应用重启。

## 二、根因

`electron-app/portable-updater.js` 的 `spawnDetached()`：

```js
spawn(exe, args, { detached: true, stdio: 'ignore', windowsHide: true, ... })
```

`windowsHide: true` 在 **detached 模式**下不生效：Windows 上 `detached: true` 会带上 `DETACHED_PROCESS`，而 `cmd.exe` 是控制台程序，于是系统给它**新建一个控制台窗口**——就是那个 ping 黑窗。也就是说「隐藏」和「脱离父进程」这两个诉求，用一种标志位组合实现不了。

## 三、修复

改为「批处理承载 + wscript 隐藏拉起」：

1. 把 `ping → robocopy → start 应用` 这条链写进临时 `.bat`；
2. 再写一个 `.vbs`：`sh.Run "cmd /c ""<bat>""", 0, False`（窗口样式 0 = 隐藏）；
3. 用 `spawn('wscript.exe', ['//B','//Nologo', vbs], { detached: true, windowsHide: true })` 拉起。

为什么这样可行：

- `wscript.exe` 是 **GUI 子系统**程序，没有控制台，`detached` 也不会新建窗口；
- `detached: true` 保证主进程退出（更新必须让应用先退出）后它仍在运行；
- `sh.Run(..., 0, False)` 以隐藏窗口启动真正干活的 `cmd`。

## 四、验证（实测，不是推断）

| 项 | 结果 |
|---|---|
| 主进程立即退出后，链式命令是否还会执行 | ✅ 延迟 4 秒后标记文件生成 |
| `cmd` / `PING` 进程是否有窗口 | ✅ `MainWindowHandle = 0`（无窗口） |
| 更新闭环 | ✅ 覆盖 → 重启应用，行为与 8093 一致 |
| 回归断言 | ✅ `verify_update_flow_e2e.mjs` **114P 0F**（新增 3 条：不用 cmd detached、wscript 隐藏、wscript detached 保活） |

## 五、影响

- 只影响 Windows 便携版的自更新（安装器链路不变）；
- 更新流程时序不变（仍是先退出应用、等待 12 秒、robocopy 覆盖、重启）；
- 旧客户端（≤1.0.8099）仍会看到黑窗，升级到 8100 后不再出现。
