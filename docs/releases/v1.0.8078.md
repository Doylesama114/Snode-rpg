# v1.0.8078

发布日期：2026-10-27。

**根因收尾**：自动更新一直卡在 `Failed to uninstall old application files: 2`，不是延迟不够，而是安装器形态用错了。

## 一、为什么一直失败

项目用的是 **assisted 安装器**（`nsis.oneClick: false` + 允许选目录）。这种形态的更新流程是「先卸载旧版本、再装新版本」，而 electron-updater 在静默模式下调用它时：

- 卸载器需要先等旧进程退出、再删除旧文件；
- 静默模式没有界面，任何一步失败都只能以退出码 2 结束；
- 结果就是每次都停在 `Failed to uninstall old application files : 2`，与应用是否延迟 12 秒无关。

electron-builder 的自动更新是为 **oneClick 安装器**设计的：直接覆盖写入，不做「先卸载」这一步。

## 二、本版改动

| 项 | 之前 | 现在 |
|---|---|---|
| 安装器形态 | `oneClick: false`（assisted） | **`oneClick: true`** |
| 安装位置 | 向导里手选 | `installer.nsh` 的 `preInit` 固定写入 **`D:\SnodeRPG`** |
| 桌面快捷方式 | 关闭 | 开启 |
| 自定义脚本 | 含 `/S` 静默处理与完成页复选框（assisted 专用） | 精简为 ASCII：Win10 检查 + 目录固定 |

`preInit` 会同时写 HKLM/HKCU 的 `InstallLocation`，安装器与更新器都以它为准，因此安装和后续自动更新都会落在 `D:\SnodeRPG`。

## 三、升级注意

从 assisted 版（≤1.0.8077）切到 oneClick 版**必须手动装一次**：两种安装器的卸载记录不兼容，自动更新无法跨形态完成。装好 1.0.8078 之后，后续更新才会走 oneClick 的覆盖式更新。
