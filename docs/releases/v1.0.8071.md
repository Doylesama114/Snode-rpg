# v1.0.8071

发布日期：2026-10-26。

修复桌面端**自动更新长期不生效**：更新链路改为国内镜像优先，下载失败或过慢会自动切源，并在本次运行内重试。

## 一、问题定位

实测（中国网络）：

| 源 | 小文件 | exe 下载 | 157 MB 预计 |
|---|---|---|---|
| GitHub | 2.4 / 3.1 s | **15 KB/s** | 约 3 小时 |
| 阿里云 OSS | 41 / 102 ms | **4,619 KB/s** | 约 35 秒 |

而 v1.0.8065 起，自动检查写成 `sources: ['github','oss']`，且 `autoUpdater.on('error')` 里的回退分支要求 `autoFallback === true`——生产路径上传的是 `false`，**回退到镜像的代码成了死代码**。于是：

1. GitHub 的 API 能通（2.4 s）→ 判为有新版本 → `setFeedURL(github)`
2. 157 MB 从 15 KB/s 的 GitHub 下载，几乎永远下不完
3. 用户关窗 → 下载中断 → 本次启动再无重试
4. `autoInstallOnAppQuit` 需要先下载成功，永远等不到

发布侧本身没问题：OSS 三件套（latest.yml / exe / blockmap）全部 200，`latest.yml` 的 sha512 与实际 exe **完全一致**。

## 二、修复内容

| # | 改动 |
|---|---|
| 1 | **镜像优先**：自动检查改为 `['oss','github']`，GitHub 仅兜底 |
| 2 | **真正启用切源**：记录已尝试源，`error` 与下载失败时自动切到尚未尝试的源（各试一次，不来回打转） |
| 3 | **低速熔断**：平均低于 100 KB/s 持续 60 秒，或 120 秒没有任何进度 → 取消本次下载并切源 |
| 4 | **本次运行内重试**：首检失败后 10 分钟、30 分钟各再试一次 |
| 5 | **安装结果校验**：安装前写入待安装版本，重启后版本没变则记录 `updater-install-not-applied` 并在启动台提示 |
| 6 | **日志完整**：更新日志保留 version/source/feed/percent/error 原文（此前只记事件名，查不到原因） |

## 三、验证

- `verify_update_flow_e2e.mjs`：新增 **16 条**断言（源顺序 / 切源 / 熔断阈值 / 重试 / 安装校验 / 日志），**36P 0F**
- 全量门禁：Clean 57/57 · Tests 913P 0F（4 项为环境缺 Electron 模块）
- 真机验证（待用户执行）：安装 1.0.8070 → 等待自动检查 → 观察 OSS 下载（应约 35 秒）→ 退出安装 → 重启后版本号应为 1.0.8071

## 四、回归方式

若更新仍不生效，请到「设置 → 导出诊断」，把 `snowd-update-state.json` 与 `desktop.log` 中的 `updater-*` 事件一并发回：现在能直接看到卡在哪个源、哪个阶段、什么错误。
