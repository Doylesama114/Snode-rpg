# v1.0.8101

发布日期：2026-11-05。

Mac 版本改为**应用内下载 + 退出即装**，不再让用户自己开浏览器下 DMG 再拖拽。

## 一、之前为什么装不上

| 环节 | 旧实现 | 后果 |
|---|---|---|
| 检查更新 | 只请求 `api.github.com` | 国内常不可达/被限流（匿名 60 次/小时/IP），直接报「检查失败」 |
| 下载 | `shell.openExternal(dmg 链接)` | 只是**用浏览器打开链接**，应用内没有任何下载 |
| 安装 | 无 | 提示「退出应用并替换」，用户不知道怎么做 |
| Gatekeeper | DMG 经浏览器下载会带 `com.apple.quarantine` | 未签名 → 双击报「已损坏/无法验证开发者」 |

## 二、现在的流程

```
检查：OSS mac.json → GitHub releases/latest/download/mac.json → GitHub API（三级回退）
下载：应用内下载 zip（进度 + sha512 校验）
安装：退出应用 → spawn /bin/sh → ditto 解压 → PlistBuddy 校验版本
      → 备份旧 .app → ditto 覆盖 → xattr 清除 quarantine → 重新启动
      ↑ 任何一步失败：自动回滚旧版本，应用仍可正常使用
```

关键点：**应用内下载的文件不会被 macOS 打上 quarantine 标记**（只有 Safari/Chrome 这类下载器才会），所以在不签名、不公证的前提下，更新过程也不会再触发 Gatekeeper 拦截。

## 三、新增能力

- `electron-app/mac-updater.js`：清单解析、架构判定（含 Rosetta：`process.arch=x64 + 运行在 ARM 翻译`时自动选 arm64 包）、sha512、可回滚安装脚本；
- `--update-selftest`：一键自检（清单源可达性、缓存目录可写、安装目录可写、当前架构），输出 JSON 便于用户回传；
- 发布产物新增 `Snode-RPG-<版本>-mac-<arch>.zip`，并由新 job 生成 `mac.json`（含各架构 url/size/sha512），同时镜像到 `releases/latest/mac.json`；
- Windows 安装包也带上 `mac-updater.js`（`main.js` 顶层 require，缺了会启动失败）。

## 五、限制

- 仍未做 Apple 签名/公证：**首次安装**（浏览器/微信下 DMG）依然需要「右键 → 打开」；从 8101 起**之后的更新不需要**；
- 老版本（≤1.0.8100）没有这套逻辑，只能手动更新一次，升级到 8101 后才会走新流程；
- 若 `/Applications` 无写权限（企业策略），会回滚并提示手动下载。
