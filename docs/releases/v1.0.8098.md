# v1.0.8098

发布日期：2026-11-03。

修复 Mac 版本：**从 v1.0.8083 起连续 13 个版本没发出 DMG，且即使发出来也会一启动就崩溃。**

## 一、问题

| 事实 | 证据 |
|---|---|
| Mac CI 从 8083 起每次都失败 | `Build macOS Installers` 在 v1.0.8083–v1.0.8095 全部 failure，最后一次成功是 v1.0.8082 |
| 失败点固定 | 第 6 步 `Build DMG installer` |
| 8082→8083 代码只差版本号 | `git diff` 只显示 `package.json` 版本行 |
| 即使构建成功也会崩 | 8083 起 `main.js` 顶层 `require('./portable-updater.js')`，而 mac 打包白名单没这个文件 |

两个叠加的根因：

1. **构建第一步就退出**：`build-mac.mjs` 先跑 `sync-check.js`，而 `sync-check` 把 `AGENTS.md` 这类纯文档也当构建阻塞项。文档一编辑，mac 构建直接 `❌ 文件不同步` 退出。
2. **打包遗漏导致启动崩溃**：`main.js` 顶层 `require('./portable-updater.js')`（8083 引入），但 `electron-builder.mac.yml` 的 `files` 白名单里没有它 → 打包后的 app 一启动就抛 `Cannot find module` → CI 的 smoke 步骤报 `Application exited during startup`。

## 二、修复

| 改动 | 说明 |
|---|---|
| `electron-app/sync-check.js` | `*.md` / README 不同步改为**警告**，不再阻断构建（非文档仍严格阻塞） |
| `electron-app/electron-builder.mac.yml` | `files` 补上 `portable-updater.js` |
| `electron-app/main.js` | `portable-updater` 改为防御性 `require` + `PORTABLE_MODE` 额外要求模块存在；mac 上缺模块不再让整个应用起不来 |
| `scripts/tests/mac-platform.test.cjs` | 新增断言：`main.js` 里每个相对 `require('./x')` 必须被 mac 白名单覆盖（防再犯） |
| `.github/workflows/build-mac.yml` | 构建日志落盘 + 失败时用 `::error::` 注解输出真实报错；签名/烟测失败也输出注解，不再只有一行 `Process completed with exit code 1` |

## 三、验证

在分支 `codex/mac-installer-fix` 上跑真实 GitHub Actions（macos-15 arm64 + macos-15-intel x64）：

```
JOB build-mac (arm64, macos-15, mac-arm64) = success
JOB build-mac (x64, macos-15-intel, mac)     = success
```

包含：DMG 构建 → `codesign --verify --deep --strict` → 启动打包后的 `.app` 烟测 → 上传产物，全链路通过。

## 四、Mac 用户的更新方式

`mac-platform.js` 已有更新检查：读取 GitHub latest release，按架构找 `Snode-RPG-<版本>-mac-<arch>.dmg`。

- 本版起每个 release 会同时提供 `-mac-arm64.dmg` 与 `-mac-x64.dmg`；
- 未做 Apple 签名/公证（`identity: "-"`、`notarize: false`），首次打开需**右键 → 打开**；
- 更新方式：下载新 DMG → 拖入「应用程序」替换。
