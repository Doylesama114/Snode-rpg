# v1.0.8104

发布日期：2026-11-06。

修复 Mac 端应用内下载报 ENOENT（no such file or directory, open ...-mac-arm64.zip）。

## 一、现象

Mac 用户在 1.0.8102 / 8103 上点更新，启动台底部报：

    下载更新失败：ENOENT: no such file or directory,
    open '/Users/<用户>/Library/Application Support/snowd-skill-tree/mac-update/Snode-RPG-1.0.8103-mac-arm64.zip'

路径是对的，目录也存在，但文件打不开。

## 二、根因：重定向时的文件竞态

旧实现（8101–8103）先打开目标文件，再判断是否 302：

    var file = fs.createWriteStream(dest);          // ① 先打开目标文件
    if (res.statusCode >= 300 && res.headers.location) {
      file.close(function () { fs.unlink(dest, ...) });   // ② 关闭后删除
      downloadToFileWithProgress(location, dest, ...);     // ③ 同时再开同一个文件
    }

GitHub 下载链接是 302 跳转（github.com → objects.githubusercontent.com），所以 ②③ 必然同时发生：

1. ③ 新建写流，文件被重新创建；
2. ② 的 unlink 回调随后执行，把 ③ 正在写的文件删掉；
3. 写入落进已删除的 inode，磁盘上没有这个名字；
4. 下载“成功”后计算 sha512 时 openSync → ENOENT。

所以这是必现问题，不是网络问题：只要走重定向就会触发。

## 三、修复

| 改动 | 说明 |
|---|---|
| 新增 electron-app/mac-download.js | 下载逻辑独立成模块，可单测 |
| 重定向阶段不碰磁盘 | 先跟完 302（最多 8 跳），拿到 200 才创建写流 |
| 完成后校验 | 文件必须存在，且大小等于 Content-Length |
| 目录按需创建 | mkdir 失败会把真实原因抛出来，不再静默吞掉 |
| 失败重试一次 | 网络中断/校验失败自动重试一次，再失败才提示手动下载 |

## 四、验证

| 测试 | 结果 |
|---|---|
| 302 → 302 → 200 重定向链（8104 回归用例） | 文件存在、内容 sha512 完全一致 |
| 目标目录不存在 | 自动创建成功 |
| HTTP 404 / 重定向死循环 | 正确报错，且不留垃圾文件 |
| 下载截断（Content-Length 不符） | 报「下载不完整」 |
| verify_update_flow_e2e.mjs | 126P 0F（新增 4 条断言） |
| mac-download.test.cjs | 3P 0F（本地起 HTTP 服务器真实跑重定向） |

## 五、注意

- 这个 bug 存在于 8101–8103，这些版本的用户仍会看到同样报错，8104 起才带修复；
- 受影响用户请手动安装一次 8104：按芯片下载 -mac-arm64.dmg（M 系列）或 -mac-x64.dmg（Intel），拖进「应用程序」，首次右键 → 打开；之后的应用内更新不再需要手动。
