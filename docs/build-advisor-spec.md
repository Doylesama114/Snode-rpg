# Build Advisor 规格书（阶段 0）

> **项目代号**：Build Advisor（法师 MVP）  
> **规格版本**：0.1.0  
> **最后更新**：2026-07-06  
> **状态**：阶段 0 — 待人工验收  
> **规则版本**：26.06.30（技能点 / 色彩标识）

本文档是 Build Advisor 的**唯一规格基准**。后续各阶段（索引脚本、检索、DeepSeek 接入、UI）均须符合本文；**未经人工验收通过，不得进入下一阶段**。

---

## 1. 产品目标

为斯诺德跑团玩家提供 **AI 辅助 build 顾问**：根据现有规则与数据，回答「如何车卡、如何升级点技能、何时选专长/进阶/兼职、有哪些 combo」等问题。

### 1.1 MVP 范围（第一版）

| 包含 | 不包含 |
|------|--------|
| **主职业：法师** | 其余 14 个主职业（后续扩展） |
| 车卡：种族 / 背景 / 属性思路 | 自动写入角色面板 |
| 法师技能树（356）+ 通用天赋树（390） | 奇械师职业技能（尚无 skill_effects） |
| 法师 + 通用进阶（门槛 / 条件 / 名称推测） | 进阶路线完整技能树（阶段 8） |
| 特殊专长（100）与升级里程碑 | DM 团队色彩结算自动化 |
| 兼职规则与兼容性 | 附赠职业剧情获取流程细节 |
| 可选：读取玩家角色快照做达标检测 | 联机 / 多人同步 |

### 1.2 两种咨询模式

| 模式 | 输入 | 输出差异 |
|------|------|----------|
| **纯咨询** | 自然语言（如「输出很猛的法师」） | 泛化 build，不标注已学/未学 |
| **带角色**（阶段 7+） | 自然语言 + `characterSnapshot` | 进阶/兼职/专长带 ✓/✗；技能标注已学/互斥 |

MVP 检索与生成层先支持**纯咨询**；`characterSnapshot` schema 在本规格中预先定义，实现可后置。

### 1.3 非目标（明确不做）

- 不替代 DM 裁决（标识发放、剧情进阶、模组条件）
- 不保证 combo 100% 规则合法；推测项必须标注
- 不在前端硬编码 API Key（MVP 用本地 CLI + `.env`）

## 2. 架构：五层知识库 + 可选角色层

```
用户问题 [+ 可选 characterSnapshot]
        │
        ▼
┌───────────────────┐
│ 意图路由 retrieve  │  ← 阶段 5 实现
└─────────┬─────────┘
          │ 按层取 Top-K chunks
          ▼
┌─────────────────────────────────────────┐
│ L0 规则摘要（常驻 system prompt）          │
│ L1 车卡库（race / background / class）   │
│ L2 技能库（法师 + 通用天赋）               │
│ L3 进阶库（法师·进阶 + 通用·进阶）         │
│ L4 专长库 + 升级里程碑表                   │
│ L5 Combo 库（人工种子为主）                │
│ L6 玩家角色快照（可选，程序算达标）         │
└─────────────────────────────────────────┘
          │
          ▼
   DeepSeek Flash 生成（阶段 6）
          │
          ▼
   结构化 + 自然语言回答
```

**原则**：DeepSeek **只读检索结果**，不读原始 `法师.json` 全文（~2 万行）。数值达标（属性、熟练度）由**程序计算**，LLM 仅组织语言。

## 3. 数据源映射（事实源）

实现阶段从下列文件**抽取**为 `advisor/` 目录下 JSON；抽取逻辑以本表为准。

### L0 — 规则摘要

| 内容 | 权威来源 | 备注 |
|------|----------|------|
| 主职 1～20 级升级表 | `斯诺德跑团/panel_data.js` → `REF_LEVELUP.main_class` | 与 `帮助.html` §升级 交叉校验 |
| 子职升级表 | `REF_LEVELUP.sub_class` | 兼职后适用 |
| 兼职门槛 + 兼容矩阵 | `斯诺德跑团/帮助.html` §兼职 | 15 职业 |
| SP / 色彩标识（26.06.30） | `项目文档.md`、`debug-journal.md` #5 | 手写摘要进 L0 |
| 幕间 / 附赠职业等 | `帮助.html` | MVP 仅摘要，不展开 |

**L0 要点（须写入 system prompt）**：

1. **技能点**：数值型 `sp_points`，学 1 个技能/天赋消耗 1 SP（除非技能另有说明）。
2. **色彩标识**：学习带「标识」的技能需持有对应颜色；标识由 **DM 团队结算**获得，顾问不得假设「打完就自动给」。
3. **兼职**：主职 7 级；须满足属性 / 熟练度 / 剧情条件；兼职业不能与「不可兼职」列表冲突。
4. **进阶**：主职 5 级开启三条进阶途径；子职 11 级开启；具体解锁看 `*·进阶.json` + 剧情条件。
5. **免责声明**：进阶名称推测、combo 推测须标注置信度。

### L1 — 车卡库

| 内容 | 权威来源 | 规模（当前） |
|------|----------|--------------|
| 种族 | `职业页/数据/races_data.js` → `RACES` | 30 |
| 个性背景 | `斯诺德跑团/panel_data.js` → `REF_BACKGROUNDS` | 需阶段 1 统计 |
| 法师职业要求 | `REF_CLASSES.法师` + `帮助.html` 兼职表法师行 | 智力 15；奥秘+知识+逻辑熟练 +6；魔法传承 |
| 法师车卡 heuristics | **新建** `advisor/chargen/mage_hints.json` | 半人工（阶段 1） |

**法师车卡优先级（heuristics 方向，供阶段 1 写入）**：

- 属性：1 级起 **智力**优先，目标 15+ 满足本职业/奇械师兼职门槛。
- 种族：智力加值（侏儒 +2、魔裔/血族/人鱼 +1、人类 +1 全属性等）；减智力种族（兽人 -1、鱼人 -1）需警示。
- 背景：提供 **逻辑 / 奥秘 / 知识** 熟练或专业项的背景优先（如学者向背景，自 REF_BACKGROUNDS 筛）。

### L3 — 进阶库

| 内容 | 权威来源 | 规模 |
|------|----------|------|
| 法师专属 + 重复通用 | `职业页/数据/法师·进阶.json` → `advancements[]` | **40**（含 10 条与通用重复） |
| 通用进阶 | `职业页/数据/通用·进阶.json` | **10**（去重后并入） |

**合并规则（阶段 3）**：以 `id` 去重；标 `scope: "mage-only" | "universal"`；`source_classes` 保留。

**进阶置信度三档**（AI 输出必须遵守）：

| 档 | 条件 | AI 允许说什么 | 必填标注 |
|----|------|---------------|----------|
| **A** | 进阶技能已入库（`*·进阶.html` / 未来 JSON） | 具体技能推荐 | `confidence: "documented"` |
| **B** | 仅有 `*·进阶.json` 元数据（attrs, conditions, cost） | 门槛、剧情条件、**名称方向推测** | `confidence: "metadata_only"` |
| **C** | 仅名称无描述 | 不得写具体数值效果 | `confidence: "name_inference"` + 免责声明 |

**MVP 全部为 B/C 档**（进阶 HTML 技能树未入库前无 A 档）。

**单条进阶 chunk 建议字段**：

```json
{
  "id": "adv-mage-冰霜法师",
  "name": "冰霜法师",
  "scope": "mage-only",
  "sourceClasses": ["法师", "魔契师"],
  "attrsRequired": { "智力": 15 },
  "markCost": [{ "name": "蓝色", "amount": 3 }],
  "conditions": ["…剧情条件…"],
  "inferenceTag": ["control", "frost"],
  "inferenceBlurb": "名称指向冰霜/控场方向，具体技能以规则书为准",
  "confidence": "metadata_only"
}
```

**属性达标（程序算，阶段 3）**：

```typescript
// 伪代码
function checkEligibility(attrs: Record<string, number>, required: Record<string, number>) {
  const gaps: Record<string, number> = {}
  for (const [k, min] of Object.entries(required)) {
    if ((attrs[k] ?? 0) < min) gaps[k] = min - (attrs[k] ?? 0)
  }
  return { eligible: Object.keys(gaps).length === 0, gaps }
}
```

## 5. 检索与生成（阶段 5～6 实现指引）

### 5.1 意图路由（关键词 → 层）

| 用户意图示例 | 优先层 | Top-K 建议 |
|--------------|--------|------------|
| 种族 / 背景 / 车卡 | L1 + L0 | 种族 5 + 背景 5 |
| 输出 / 爆发 / 塑能 | L2 mage + L2 universal | 各 15～20 |
| 进阶 / 冰霜法师 | L3 + L6 eligibility | 5～10 |
| 4 级专长 | L4 + L0 里程碑 | 专长 10 |
| 兼职 | L0 multiclass + L6 | 兼容子职列表 |
| combo | L5 | 5 |

### 5.2 System prompt 硬规则

1. **仅引用** context 中出现的技能/专长/进阶/种族/背景 **名称**。
2. 未检索到的名称 → 回答「当前资料未收录，请查规则书或 DM」。
3. 进阶 B/C 档 → 必须出现「具体效果以规则书为准」或同等免责声明。
4. Combo 非 `documented` → 必须标注「推测」。
5. 标识 / SP → 提醒 DM 结算，不得编造玩家已有标识。
6. 不得把 D&D 规则套用到斯诺德（见 `帮助.html` §2）。

### 5.3 输出结构（模板）

```markdown
## 流派理解
（1～2 句）

## 车卡建议（若相关）
- 种族：…
- 背景：…
- 属性：…

## 等级路线
### 1～3 级
- …

## 里程碑
- 4 级专长：…
- 5 级进阶方向：…（✓/✗ 属性）

## 通用天赋（若相关）
- …

## Combo（若有）
- … [documented|推测]

## 提醒
- 标识/SP/DM/互斥技能…
```

## 7. 分阶段交付与验收门槛
