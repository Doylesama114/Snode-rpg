## 1. 要解决什么问题

现在已有 **497 / 2229 条技能**被拆成结构化数据（游荡者 83 定稿 + 法师 414 合并稿），
但它们只存在于 markdown 里，无法查询、无法展示、无法被角色系统调用。

本设计要回答三个问题：

1. **怎么存**——2229 条技能，每条包含「固定字段 + 极异构的效果步骤 + 原文 + 成长规则」，怎么放进 PostgreSQL；
2. **怎么查**——按名称搜、按维度筛（机制/元素/能力类型）、按引用关系回溯；
3. **怎么改**——规则会持续调整，改了之后历史版本怎么办、老角色怎么办。

---

## 2. 核心模型：三层

```
skills            一行 = 一个技能的一个版本
  └ skill_steps   一行 = 该技能的一个效果步骤（按 order_index 排序）
      └ params    JSONB，该引擎的参数（异构，不拆列）
```

### 为什么是这三层

| 层 | 拆的理由 |
| --- | --- |
| skills | 需要按名称、职业、风格、阶位、状态筛选和搜索 |
| skill_steps | 需要**改单步**、**排序**、**按引擎反查**、**逐步审计** |
| params（JSONB） | 65 个引擎的参数完全不同（`E01` 是伤害骰、`E08` 是召唤模板、`E30` 是修正目标），拆成列或子表会变成 EAV 灾难 |

### 被否决的方案

| 方案 | 否决理由 |
| --- | --- |
| 整个 effects 存一个 JSONB 在 skills 上 | 改一步要重写整块，git diff 看不到改了什么，无法按步骤审计 |
| 步骤参数拆成 `step_params(step_id, key, value)` | EAV 模式。查一个技能要 join 几十行，且没有类型保障 |
| 65 个引擎各建一张参数表 | 表爆炸，跨引擎查询要 65 路 UNION |

## 3. 表结构

### 3.1 `skills` —— 技能（每版本一行）

```ts
import { pgTable, uuid, text, integer, boolean, jsonb, timestamp, index, uniqueIndex } from "drizzle-orm/pg-core";

export const skills = pgTable("skills", {
  id: uuid("id").defaultRandom().primaryKey(),

  // ── 逻辑身份（跨版本稳定）──
  skillKey: text("skill_key").notNull(),   // 'rogue-backstab'，永不变
  version: integer("version").notNull().default(1),

  // ── 展示字段 ──
  name: text("name").notNull(),
  form: text("form").notNull(),            // 'skill' | 'talent'
  classSlug: text("class_slug"),           // 'rogue'；领域条目为 null
  style: text("style"),
  tier: text("tier"),

  // ── 施展段（定值，用列）──
  actionCost: text("action_cost"),         // 'main'|'bonus'|'reaction'|'none'|null
  rangeText: text("range_text"),
  durationText: text("duration_text"),
  fatigueCost: text("fatigue_cost"),       // 有骰式（1D3），故 text
  usesText: text("uses_text"),             // '短休/长休(2)'
  uniqueKey: text("unique_key"),           // 唯一性技能的分组键

  // ── 内容 ──
  rawText: text("raw_text").notNull(),     // 原文（含召唤物数据块）
  limitations: text("limitations"),
  growth: jsonb("growth").$type<GrowthRule[]>(),

  // ── 检索辅助（从 effects 提炼，避免深挖 JSONB）──
  damageTypes: text("damage_types").array(),   // ['火焰','雷电']
  engineCodes: text("engine_codes").array(),   // ['E13b','E01']，GIN 索引
  hasSummon: boolean("has_summon").notNull().default(false),
  hasAoe: boolean("has_aoe").notNull().default(false),

  // ── 版本与状态 ──
  status: text("status").notNull().default("todo"),   // todo|draft|final|blocked
  coverage: text("coverage"),                          // clean|partial|blocked
  introducedIn: text("introduced_in").notNull(),       // '2026.10'
  retiredIn: text("retired_in"),                       // null = 现行
  isCurrent: boolean("is_current").notNull().default(true),

  sourceDoc: text("source_doc").notNull(),
  createdAt: timestamp("created_at", { withTimezone: true }).defaultNow().notNull(),
  updatedAt: timestamp("updated_at", { withTimezone: true }).defaultNow().notNull(),
}, (t) => [
  uniqueIndex("skills_key_version_uq").on(t.skillKey, t.version),
  index("skills_class_idx").on(t.classSlug),
  index("skills_current_idx").on(t.isCurrent),
  index("skills_status_idx").on(t.status),
  index("skills_name_trgm_idx").using("gin", t.name.op("gin_trgm_ops")),
]);
```

**关键设计**：
- `skillKey` 是**跨版本稳定**的逻辑标识，`version` 递增。同一条技能改版 = 新增一行，旧行保留（D164 永久保留）。
- 查询现行版本用 `is_current = true`，查历史用 `skillKey + version`。
- `name` 上建 `gin_trgm_ops` 索引 → 支持模糊搜索（D163）。

### 3.2 `skill_steps` —— 效果步骤

```ts
export const skillSteps = pgTable("skill_steps", {
  id: uuid("id").defaultRandom().primaryKey(),
  skillId: uuid("skill_id").notNull().references(() => skills.id, { onDelete: "cascade" }),
  orderIndex: integer("order_index").notNull(),   // 结算顺序
  engine: text("engine").notNull(),               // 'E01' … 'E68'
  timing: text("timing"),                         // 'before'|'after'|'onHit'|null
  owner: text("owner"),                           // 'self'|'target'|'summon'|null
  condition: text("condition"),                   // 表达式原文
  outVar: text("out_var"),                        // 产出变量名
  params: jsonb("params").notNull().$type<Record<string, unknown>>(),
  growth: jsonb("growth").$type<Record<string, Partial<StepPayload>>>(),
  usesLimit: jsonb("uses_limit"),                 // 步骤级次数（D: EffectStep.uses）
}, (t) => [
  uniqueIndex("steps_skill_order_uq").on(t.skillId, t.orderIndex),
  index("steps_engine_idx").on(t.engine),
  index("steps_params_gin").using("gin", t.params),
]);
```

### 3.3 `skill_keywords` —— 七维度标签

```ts
export const skillKeywords = pgTable("skill_keywords", {
  id: uuid("id").defaultRandom().primaryKey(),
  skillId: uuid("skill_id").notNull().references(() => skills.id, { onDelete: "cascade" }),
  category: text("category").notNull(),  // 技能与天赋|攻击类型|能力类型|元素属性|机制标签|效果标签|特殊标签
  value: text("value").notNull(),
}, (t) => [
  uniqueIndex("kw_uq").on(t.skillId, t.category, t.value),
  index("kw_lookup_idx").on(t.category, t.value),
]);
```

### 3.4 `skill_refs` —— 能力引用

```ts
export const skillRefs = pgTable("skill_refs", {
  id: uuid("id").defaultRandom().primaryKey(),
  fromSkillId: uuid("from_skill_id").notNull().references(() => skills.id, { onDelete: "cascade" }),
  toKeyword: text("to_keyword"),
  toName: text("to_name").notNull(),
  resolvedSkillKey: text("resolved_skill_key"),   // 解析到逻辑键，不绑版本
  resolveStatus: text("resolve_status").notNull(), // resolved|ambiguous|unresolved
}, (t) => [
  index("refs_from_idx").on(t.fromSkillId),
  index("refs_to_idx").on(t.resolvedSkillKey),
]);
```

### 3.5 `engines` —— 引擎字典

export const engines = pgTable("engines", {
  code: text("code").primaryKey(),          // E01…E68

  params: jsonb("params"),                  // 参数签名

### 3.6 `character_skill_decisions` —— 技能被删除时的待决策

```ts
export const characterSkillDecisions = pgTable("character_skill_decisions", {
  id: uuid("id").defaultRandom().primaryKey(),
  characterId: uuid("character_id").notNull(),
  retiredSkillId: uuid("retired_skill_id").notNull().references(() => skills.id),
  replacementSkillId: uuid("replacement_skill_id").references(() => skills.id),
  status: text("status").notNull().default("pending"),  // pending|keep|migrated
  decidedAt: timestamp("decided_at", { withTimezone: true }),
  createdAt: timestamp("created_at", { withTimezone: true }).defaultNow().notNull(),
}, (t) => [
  index("decisions_pending_idx").on(t.status),
]);
```

对应 D162：日常改动全局生效；**只有技能被删除时**，持有者收到一条待决策记录，二选一（保留旧版 / 迁移）。

## 4. 数据契约

```ts
// packages/contracts/src/skill.ts

export type SkillForm = "skill" | "talent";
export type SkillStatus = "todo" | "draft" | "final" | "blocked";
export type KeywordCategory =
  | "技能与天赋" | "攻击类型" | "能力类型" | "元素属性"
  | "机制标签" | "效果标签" | "特殊标签";

export interface SkillStep {
  order: number;
  engine: string;
  timing?: "before" | "after" | "onHit";
  owner?: "self" | "target" | "summon";
  condition?: string;
  out?: string;
  params: Record<string, unknown>;
  growth?: Record<string, Partial<SkillStep>>;
}

export interface SkillSummary {
  id: string;
  skillKey: string;
  version: number;
  name: string;
  form: SkillForm;
  classSlug: string | null;
  style: string | null;
  tier: string | null;
  actionCost: string | null;
  fatigueCost: string | null;
  keywords: { category: KeywordCategory; value: string }[];
  status: SkillStatus;
}

export interface SkillDetail extends SkillSummary {
  rawText: string;
  rangeText: string | null;
  durationText: string | null;
  usesText: string | null;
  steps: SkillStep[];
  refs: { keyword: string | null; name: string; status: string }[];
  sourceDoc: string;
  introducedIn: string;
  retiredIn: string | null;
}

export interface SkillQuery {
  q?: string;
  className?: string;
  form?: SkillForm;
  keywords?: { category: KeywordCategory; value: string }[];
  actionCost?: string;
  status?: SkillStatus;
  includeRetired?: boolean;
  page?: number;
  pageSize?: number;
}

export interface SkillListResponse {
  items: SkillSummary[];
  total: number;
  page: number;
  pageSize: number;
}
```

## 5. 一个完整例子：背刺

### 入库后的三张表

```
skills
  skill_key = 'rogue-backstab'  version = 1  name = '背刺'
  form = 'skill'  class_slug = 'rogue'  style = '暗影风格'  tier = '一阶天赋树'
  action_cost = 'main'  range_text = '近战'  duration_text = '立即'  fatigue_cost = '1'
  raw_text = '你对目标的后背…'  is_current = true  status = 'final'
  engine_codes = {E13b,E01}  damage_types = {}

skill_steps
  (order=0, engine='E13b', params={sector:'背面'}, out_var='isBehind')
  (order=1, engine='E01', params={attackType:'近战攻击', hitBonus:'+2*isBehind', post:'+1D4'},
                growth={'3':{params:{post:'+2D4'}}, '6':{params:{post:'+3D4'}}})

skill_keywords
  ('技能与天赋','技能')  ('攻击类型','近战攻击')  ('能力类型','战技')
```

### 三个查询实际长什么样

```sql
-- ① 模糊搜索
SELECT name FROM skills
WHERE is_current AND name ILIKE '%背刺%'   -- trigram 索引生效
ORDER BY similarity(name,'背刺') DESC LIMIT 20;

-- ② 按维度筛：所有「位移」机制的「战技」
SELECT DISTINCT s.name FROM skills s
JOIN skill_keywords k ON k.skill_id = s.id
WHERE s.is_current
  AND k.category='机制标签' AND k.value='位移'
  AND EXISTS (SELECT 1 FROM skill_keywords k2 WHERE k2.skill_id=s.id
              AND k2.category='能力类型' AND k2.value='战技');

-- ③ 改版影响面：删掉「毒刃」会影响谁
SELECT s.name FROM skill_refs r
JOIN skills s ON s.id = r.from_skill_id
WHERE r.resolved_skill_key = 'rogue-poison-blade' AND s.is_current;
```

## 6. 改版与删除的完整流程

### 6.1 改一个数值（最常见）

```
火球术 4D6 → 5D6
  1. 新增 skills 行：同 skill_key='mage-fireball'，version=2，is_current=true
  2. 旧行 is_current=false，retired_in='2026.11'
  3. 新行复制 skill_steps，只改第 2 步的 params.damageDice
  4. 角色不迁移（全局生效，D162）
```

git diff 只会显示：新增一行 skills + 一行 steps 的参数变化。

### 6.2 删除一个技能

```
  1. 该 skill_key 所有版本 is_current=false，retired_in='2026.11'
  2. 查持有它的角色 → 为每人写一条 character_skill_decisions(status='pending')
  3. 玩家界面提示：「毒刃已在新版移除。保留旧版 / 迁移到毒刃·改」
  4a. 选「保留」→ status='keep'，角色仍绑定旧版 skills.id
  4b. 选「迁移」→ status='migrated'，角色绑定 replacement_skill_id
  5. 旧数据**永久保留**（D164），供怀旧版/历史查看
```

### 6.3 什么时候不给选择权

用户说明：多数删除会给选择，但并非全部。数据层统一写 `character_skill_decisions`，
**不给选择的情况直接写 `status='migrated'`**（系统自动迁移），流程一致，只是少了玩家那一步。

## 7. 导入管线（从 markdown 到数据库）

```
docs/migration/<职业>/04_步骤序列_合并稿.md
        ↓  解析（已有脚本：merge4.py 一类）
JSON（每技能：name, fields, steps[], keywords[]）
        ↓  规范化（skill_key 生成、关键词拆维度、引擎参数校验）
        ↓  写入（幂等 upsert：按 skill_key + version）
PostgreSQL
```

**幂等性**：重复导入同一版本不产生新行，只更新 `status`/`coverage`。
**校验**：导入前跑一次断言——每个 step.engine 必须在 `engines` 表里，否则拒绝导入。

## 8. 索引与性能预估

| 场景 | 索引 |
| --- | --- |
| 模糊搜索 | `skills.name` GIN trigram |
| 按职业/风格浏览 | `skills.class_slug`、`skills.is_current` |
| 多维筛选 | `skill_keywords(category, value)` |
| 按引擎反查 | `skill_steps.engine` |
| 深层参数查询 | `skill_steps.params` GIN |
| 引用回溯 | `skill_refs.resolved_skill_key` |

数据量级：2229 条技能 × 平均 3 步 ≈ 7000 行 steps，加上关键词约 2 万行。
**这个量级索引不是瓶颈**，瓶颈会在搜索排序和前端渲染。
