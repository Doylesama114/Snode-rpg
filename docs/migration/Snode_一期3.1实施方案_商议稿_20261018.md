## 1. 我方交付范围

### 1.1 一期文档原文与我方理解

| 编号 | 文档原文 | 我方理解（可验收的形态） | 旧仓库对应资产 |
| --- | --- | --- | --- |
| **3.1.1** | 整理并迁移旧仓库中的种族、职业、技能、装备等数据和规则，实现资料展示、搜索与查询 | 统一的资料发布包 + 搜索/筛选 API + 完整详情页（正文、表格、图片、召唤单位全部固有能力） | `职业页/` 18 个职业页 + 通用天赋树 + 特殊专长；`advisor/` 语料；根目录 docx/xlsx |
| **3.1.2** | 重建角色创建流程，支持种族、职业、属性、技能和起始装备的选择，并按原有规则完成计算与校验 | 分步建卡向导 + 纯计算层 + 校验层 + 正式创建一次性授予起始资产 | `斯诺德跑团/角色创建页.html`、`panel_engine.js` 中的计算与校验、`character_*.js` |
| **3.1.3** | 重建角色面板，支持属性与状态更新、升级、技能和装备管理，并迁移原有角色数据的导入导出功能 | 角色面板（编辑/成长/学习/装备/状态）+ 云端历史 + 旧 JSON/XLSX 导入导出与往返 | `斯诺德跑团/角色面板.html` + 12 个 `character_*.js` + `panel_engine.js` |

### 1.2 本期明确不做

- 地图、棋子、战斗与检定自动化、DM 剧情编排、AI 生成、原生桌面端（一期文档 §2.3）。
- 玩家间交易、交易行、拍卖（一期文档 §2.3 保留待议）。
- 卡牌对战（`poker-game-main`）与 AI 顾问（`advisor-server`）不随本期迁移，另行决定。
- **不把旧仓库的 Electron / Android 壳搬过去**——新项目是网页优先，桌面壳是否保留另行评估。

### 1.3 我对"迁移"的定义（重要，避免误解）

不是把旧代码搬进新仓库，而是：**保留内容与结论，重建身份、关系、存储与界面**。

| 保留 | 重做 |
| --- | --- |
| 规则正文、世界观、已核对的计算结论、来源证据（docx 定位） | 稳定编号与版本、引用关系、发布机制 |
| 职业/技能/领域/装备的**分类习惯**与检索词 | 统一资料库、全文组件、React 界面 |
| 角色的**原始事实**（UID、来源、获取途径、玩家原文） | 云端身份、权限、事务、历史 |
| 已被验证的算法（属性购点、HP/FP、负重、栏位） | 前后端同源的纯函数与校验层 |

## 2. 双方现状（2026-10-18 核对）

### 2.1 旧仓库（我方）

- 版本 **v1.0.8063**，HEAD `131abb5`（2026-10-18），工作区干净。
- 规模：**18 个基础职业页 + 通用天赋树 + 特殊专长**，搜索索引 **2898 条**；牧师页 395 条（含 7/10 已公布神圣领域）；进阶详情 55 条。
- 数据源为根目录 docx/xlsx（地面真值），有完整的提取→生成→门禁管线（`scripts/` 417 个文件、根目录 61 个 `verify_*` 门禁 + `scripts/` 38 个）。
- 已知问题（迁移要解决的）：上传/学习/技能树/搜索四套数据不一致；同名技能按名合并丢来源；召唤物详情只剩摘要；旧档依赖角色名与槽位。

### 2.2 目标仓库（`Usokyun/Snode`，私有）

- `main` HEAD **`929cd8c`（2026-10-02）**，自 10-02 起无推送。
- 现状是工程骨架：React 19.3 + Vite 8.3 首页、Fastify 5 的 `/api/health` 与 `/api/ready`、`packages/contracts` 仅 health/ready 类型、`packages/db` 仅一张 `users` 表、CI 会起 Postgres 跑 `pnpm check`。
- **存在 23 个尚未推送的本地候选改动**（分支 `codex/character-management-implementation0`），内容是角色管理的本机预览：`#/characters` 路由、`CharacterWorkspace.tsx`、编辑核心、草稿检查点、IndexedDB 适配、浏览器验收。它们目前只存在于我们的调研快照中。

### 2.3 已有调研（10-06，可直接复用）

- [总体计划（182 行）](Snode_一期迁移总体计划_协作审阅版_20261006.md)、[技术参考（18 章 77 KB）](Snode_迁移技术参考_详细版_v1_20261006.md)、[资料库与角色关联方案](Snode_资料库与角色关联及规则升级方案_20261006.md)。
- 契约与样例：B1–B6、T04–T07、C01（战士 22/119 项机制审查）。
- 领域模型候选 v0.2.2：[T07_领域类型_v0.2.2.ts](交接包/Snode_一期迁移协作审阅包_20261006_v1/02_深入说明/T07_领域类型_v0.2.2.ts)（335 行，含 `CharacterDocument`、`AbilityEntry`、`AcquisitionRecord`、`LearnedAbility`）。

### 2.4 三条需要正视的差距

1. **目标仓库冻结 16 天，候选改动未推送**——如果你们本地机器或分支丢失，角色管理核心只剩一份不能直接运行的快照。
2. **我方基线漂移 39 个提交**——调研记录旧仓库基线是 `83109027`（v1.0.8043，10-06），现在是 `131abb5`（v1.0.8063）；索引从 2791 条涨到 2898 条。实施前必须重新登记基线。
3. **两套工程规范不同**——新仓库 Node 24 / pnpm 11.9 / TS 7 / strict 全家桶；旧仓库无构建、无 workspace。迁移代码必须按新仓库规范写。

## 3. 建议分期（M0–M4）

> 只写顺序与完成条件，**不承诺日历日期**。每一期结束都有可演示的东西。

| 阶段 | 交付 | 依赖 3.2 | 完成证据 |
| --- | --- | --- | --- |
| **M0 基线与契约** | 旧仓库基线快照、领域类型 v0.3 收敛、8 项决定签批、第一批 PR 结构 | 无 | 基线 JSON（commit/哈希/条目数）+ 签批记录 + CI 通过的空骨架 PR |
| **M1 资料库首批闭环**（3.1.1） | 1 个职业 + 1 个神圣领域 + 1 个召唤单位（含全部固有能力）的 release 包、搜索/详情 API、资料页 | 无（可独立） | 同一份资料在资料页/技能树/详情三处一致；同名异源可分；单位全部固有能力可读 |
| **M2 角色文档与建卡**（3.1.2） | `CharacterDocument` 落库、8 步建卡向导、纯计算与校验、正式创建 + 起始资产只授予一次 | **3.2.1**：身份、角色存储、事务 | 一个合法组合从选择到落库；刷新/换设备可读；重复提交不重复授予 |
| **M3 面板·成长·装备**（3.1.3 前半） | 面板编辑、升级、学习/遗忘、栏位与永久禁学、来源池、配装 | 3.2.1 + 3.2.3（资产） | 学习扣费原子；满栏需玩家决定；历史恢复不绕过永久限制 |
| **M4 旧档与全量**（3.1.3 后半） | 旧 JSON/XLSX 导入、差异预览、待核对角色、新格式导出往返、全量覆盖清单 | 3.2.1 + 3.2.3 | 真实档案往返；UID 与原文不丢；未确认项不自动学习 |

**为什么这样切**：M1 对外只读、无身份依赖，可以立刻开工并给群组试用；M2 之后的每一步都卡在 3.2 的接口上，所以接口必须先谈。

## 4. 与 3.2 的接口清单

### 4.1 我们需要 3.2 提供（按优先级）

| # | 接口 | 用到它的阶段 | 说明 |
| --- | --- | --- | --- |
| I1 | 已验证身份（`verifiedUserId`） | M2 | 不能来自前端或上传文件 |
| I2 | 角色存储：`owner + revision + JSONB 文档 + 不可变快照` | M2 | 我们提供文档 Schema 与校验，你们提供存储与并发检查 |
| I3 | 事务与幂等：`commandId + payloadHash + 回执` | M2 | 建卡、学习、配装必须"要么全成要么全不成" |
| I4 | 字段级权限策略（绑定角色与 DM） | M2 | 前端 `editable` 只是显示，不构成授权 |
| I5 | 资产接口：钱包、库存、物品实例 | M3 | 3.1 只输出"规则计划"，由 3.2 权威写入 |

### 4.2 我们向 3.2 提供

| # | 产出 | 形态 |
| --- | --- | --- |
| O1 | 领域类型与文档 Schema（`CharacterDocument` / `DefinitionRecord` / `AbilityEntry`） | `packages/model`（纯类型，无 IO） |
| O2 | 校验与纯计算：`validateDocument`、`RuleView`、`OperationPreview` | 纯函数 + 单测 |
| O3 | 角色编辑适配器：`CharacterDocumentAdapter` 实现 | 对接你们已有的 `ManagementView` 投影 |
| O4 | 资料发布包与只读 API | `catalog` 模块 |
| O5 | 导入计划（差异、待核对、资产声明） | 结构化 JSON，交 3.2 审批入账 |

### 4.3 共同维护

- `packages/contracts`：传输 DTO（请求/响应/错误码），**双方共同 review**。
- `packages/db`：迁移文件与代码同一次 PR；我们提交 catalog 表迁移，你们提交身份/团/资产表迁移。
- 字段注册表（fieldRef → 类型 / 范围 / 谁能改）：新增字段走 PR，不静默扩。

## 5. 待共同拍板（本次商议重点）

> 每项都给出我方建议与理由；同意 / 修改 / 留待后续，请在会上直接记。

| # | 事项 | 我方建议 | 理由 |
| --- | --- | --- | --- |
| **Q1** | 包边界：领域类型放哪 | 新增 `packages/model`（纯类型 + 校验），`apps/api/src/catalog` 放读取，`packages/contracts` 只放传输 | 与调研 D01 一致；避免 contracts 变成什么都装的口袋 |
| **Q2** | M1 资料发布形态 | **先文件形态**（构建期生成不可变 release：JSON + 资源 + 哈希），API 只读；8 张表在 M2 前入库 | 资料只读、变更低频；先跑通闭环，不让 DB 迁移阻塞；类型与校验代码不变，后入库不返工 |
| **Q3** | `packages/contracts` 冻结节奏 | 每个 M 阶段开始前冻结一次，冻结期内只加不改 | 避免两边各改一版 |

| **Q5** | 字段权限白名单由谁定 | 我们给 fieldRef 清单与语义，你们定"谁能改" | 规则归我们，权限归服务 |
| **Q6** | 事务边界（必须原子的 4 件事） | ①建卡+起始资产 ②学习/升级+扣费 ③配装+库存 ④导入批准+资产入账 | 这四件任何一件半成功都会造成重复发放或资产不一致 |
| **Q7** | 资产接入时点 | M3 前完成 I5；M1/M2 可先用"资产声明"占位，不入真实钱包 | 一期文档把经济放在 3.2.3，但配装在 3.1.3 |

## 7. 验收与证据

每个阶段交付时附一份记录，字段固定：`runId / caseId / commit / contracts 版本 / release 哈希 / DB 迁移号 / 环境 / 夹具 / 浏览器 / 结果 / 证据路径`。

| 阶段 | 最低验收 |
| --- | --- |
| M1 | 资料页与 API 返回同一 release；同名异源可区分；单位全部固有能力可见；360/390/1440 无横向溢出 |
| M2 | 合法建卡落库；重复提交不重复授予；并发编辑冲突可见并可处理；刷新/换设备可读 |
| M3 | 学习扣费原子；满栏决策可追溯；永久禁学不可被恢复绕过；配装与库存一致 |
| M4 | 真实档案往返；UID/原文/未确认项保留；资产声明需 DM 批准后才入账 |

**不做的声明**：不把构造样例当全量验收；不把 health/ready 当业务联调；不把本机 IndexedDB 当云端。

## 8. 协作机制

- 从 `main` 开短分支，一个任务一个 PR；PR 描述按仓库模板写"变更 / 验证 / 协作事项"。
- 涉及 `packages/contracts`、`packages/db`、共享字段的改动，**提前一个 PR 通知**，不夹带。
- 每次 PR 附本地验证命令与结果；CI 绿是底线，不是完成。
- 飞书任务号与 issue 标题对应（`[任务] 3.1.1 …`），进度写 issue。
- 争议先记录成"待决"，不阻塞已验证的部分；未决项不得标完成。

## 9. 风险与前置条件

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 目标仓库冻结、候选未推送 | 管理核心可能丢失或与快照不一致 | Q8 优先确认；必要时把快照转成可运行分支 |
| 旧仓库基线漂移（+39 提交） | 资料清单与数量对不上 | T-01 重新登记；以 v1.0.8063 为基线 |
| 2898 条技能全量转换成本高 | M1 拖成大工程 | 只做"结构覆盖"切片：普通技能 + 同名异源 + 领域/跨表 + 1 个完整单位 |
| 两套工程规范差异 | 代码风格/依赖方向冲突 | 所有新代码按新仓库 tsconfig 与 CI 写，不迁旧工具链 |
| 装备与资产边界 | 配装写出真实库存，难回滚 | Q6/Q7 先定事务与占位策略 |
| 规则未决项（奇械师、色彩标识、召唤兽成长） | 自动计算出错 | 未决项保留原文 + 待核对，不自动计算 |
