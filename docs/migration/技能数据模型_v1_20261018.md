# 技能数据模型 v1（设计稿）

> 日期：2026-10-18 ｜ 状态：设计稿，未实施 ｜ 配套图：[03_技能数据模型.svg](assets/技能数据_20261018/03_技能数据模型.svg)
> 依据：[技能数据调研](技能数据调研_20261018.md)、MDPro3 / Scryfall / Foundry PF2e / Lancer 的公开实现。

---

## 1. 一句话

**技能不是一个"记录"，而是一个版本化的规则对象**：稳定身份 + 不可变修订 + 位置条目 + 发布快照 + 后置行为。
旧站的病根不是用了 JSON，而是"名字即身份、内容即位置、效果即描述"这三件事混在一起。

---

## 2. 为什么不是纯 EAV

参考项目都不是"所有字段摊平成键值对"：

| 项目 | 做法 | 对我们的启示 |
| --- | --- | --- |
| MDPro3 / YGOPro | `data` 放类型、种族、攻击力等**位掩码/数值**；`text` 放整段描述 | 热字段结构化，冷文本独立 |
| Scryfall | `oracle_id`（规则对象）与 `id`（印次）分开；`keywords` 数组、`legalities` 映射；`oracle_text` 单独 | 身份分层；可检索字段独立 |
| Foundry PF2e | 33 种"规则元素"组成数组，由系统解释 | 行为不进描述文本 |
| Lancer COMP/CON | JSON 数据包 + `.lcp` 内容包 | 发布 = 可加载的包 |

所以采用**混合存储**：热字段列化/子表化，温字段进字段表，冷内容进内容块，检索另做物化。

---

## 3. 五个层

| 层 | 表 | 职责 | 关键约束 |
| --- | --- | --- | --- |
| **来源** | `source_document` | 一次导入对应的 docx、版本、哈希 | 同一文件可重放 |
| **身份** | `skill_identity`、`skill_alias` | 稳定 ID、类型、别名 | ID 永不变；改名只加别名 |
| **内容** | `skill_revision` + `skill_field` / `skill_mark` / `skill_condition` / `skill_content_block` / `skill_upgrade` / `unit_template` | 一次修订的全部事实 | 修订不可变；草稿可改 |
| **位置** | `ability_entry` + `class / style / tier` 字典 | 技能出现在哪个职业、风格、阶位 | 位置变了不影响内容 |
| **发布** | `release`、`release_entry`、`search_doc` | 锁定一批修订；生成检索文档 | 发布不可覆盖，可回滚 |
| **行为**（后置） | `effect_handler`（代码注册表） | 战斗效果 | 不进数据字段 |

## 4. 字段字典 v1（热 / 温 / 冷）

### 4.1 分级定义

- **热（H）**：要筛选、要排序、要给战斗直接消费。**类型化列或子表 + 索引**。
- **温（W）**：要编辑、要展示，偶尔等值筛选。**进 `skill_field`，带类型与原文**。
- **冷（C）**：大段富文本、模板、附件。**进 `skill_content_block` / 子表，不进索引**。

### 4.2 字典

| 字段 | 级 | 存法 | 可筛选 | 备注 |
| --- | :-: | --- | :-: | --- |
| 技能类型 kind | H | `skill_identity.kind` | 是 | 技能 / 天赋 / 图纸 / 领域能力 |
| 职业 / 风格 / 阶位 | H | `ability_entry` | 是 | 位置，不是内容 |
| 关键词 | H | `skill_keyword` 子表 | 是 | 有序；99% 覆盖 |
| 标识（费用） | H | `skill_mark`（序号、颜色、分组） | 是 | 一个点一行；41% 多色 |
| 疲劳消耗 | H | 数值列 + 原文 | 是 | 含"-"与空白 |
| 施展时间 | H | 枚举 + 原文 | 是 | 动作/附赠/反应/仪式… |
| 施展距离 | H | 数值 + 单位 + 形态 + 原文 | 是 | 近战/自身/接触/射程 |
| 持续时间 | H | 枚举 + 数值 + 原文 | 是 | 立即/轮/小时/专注 |
| 前置条件 | W | `skill_condition` | 否 | 存结构与原文，**暂不判定** |
| 额外条件 | W | `skill_condition` | 否 | 三种触发：进度/风格/本场 |
| 施展条件 | W | `skill_condition` | 否 | 持武器、发声等 |
| 施展限制 | W | `skill_condition` | 否 | 倒地、禁锢等 |
| 升级行 | W+C | `skill_upgrade`（等级）+ 内容块 | 等级可 | 等级热，正文冷 |
| 图纸字段 | W | `skill_field` | 价格/负重可 | 研发材料/时间/价格/负重/类别 |
| 描述 | C | `skill_content_block` | 全文检索 | 段落/表格/图片/彩色文字 |
| 召唤物 | C | `unit_template` | 否 | 属性 + 全部固有能力 |
| 其他描述 | C | `skill_content_block`（具名块） | 否 | 不合并，按标题分块 |

> 关键：**"可筛选"不是"可计算"**。热字段先保证能筛能排，战斗解释放到行为层。

## 5. 内容包（pack）格式

转换器的输出、DM 后台的导出、未来第三方内容，都使用同一个包结构（参考 Lancer 的 `.lcp`、BabelCdb 的 cdb）。

```json
{
  "packVersion": 1,
  "source": { "file": "基础职业-守望者.docx", "hash": "sha256:…" },
  "skills": [
    {
      "id": "skill:watchman-xiaozhi",
      "kind": "skill",
      "aliases": [{ "source": "docx", "text": "挫志打击" }],
      "entries": [{ "classId": "watchman", "styleId": "guard", "tier": 1 }],
      "revision": {
        "rev": 1,
        "state": "draft",
        "fields": {
          "cast_time": { "raw": "1动作", "value": "action" },
          "range":     { "raw": "近战", "value": "melee" },
          "duration":  { "raw": "立即", "value": "instant" },
          "fatigue":   { "raw": "2", "value": 2 }
        },
        "keywords": ["战技", "近战攻击"],
        "marks": [],
        "conditions": [],
        "content": [{ "type": "paragraph", "text": "你对敌人发起攻击…" }],
        "upgrades": []
      }
    }
  ]
}
```

规则：

- 包里没有"表结构"概念，只有对象；写库时由服务端展开到各表。
- 每个字段都可带 `raw` 与 `value`；解析失败时 `value` 缺失、`parseStatus = "unparsed"`。
- 包带哈希；同一哈希重复导入应得到同一个变更集（幂等）。

## 6. 读写路径

| 角色 | 读什么 | 写什么 |
| --- | --- | --- |
| 转换器 | 无（只读 docx） | `source_document` + 草稿修订 + 变更集 |
| DM 后台 | 当前修订、release 列表 | 草稿修订（同一变更集入口） |
| 发布流程 | 变更集 | `release` + `release_entry` + `search_doc` |
| 玩家端 | `release` 与 `search_doc` | 无（角色数据另算） |
| 战斗（后置） | `release` + handler | 无 |

**唯一写入口是变更集**：docx 导入和手工编辑都产出变更集，审核后落修订，再发布。

---

## 7. 检索

- `search_doc` 按 release 物化，字段：`skill_id / release_id / name / aliases / keywords / marks / class / style / tier / text`。
- 列表筛选走 `search_doc` 的结构化列；全文走 GIN / tsvector（或后续接 Meilisearch）。
- 发布时重建，不实时拼表——对应 MDPro3 的 `cards_Lite` 和 Scryfall 的 bulk data。

---

## 8. 版本与角色

- 角色学到的技能引用**具体修订**，不是"最新版"。
- 发布新 release 后，系统比对：已学技能引用的修订是否过期 → 生成"跟随提案"。
- 接受 = 切到新修订；拒绝 = 保留旧引用。改名不触发提案（身份没变）。

---

## 9. 与旧站的映射

| 旧站 | 新模型 |
| --- | --- |
| `职业页/数据/{职业}.json` 的 `skills[]` | 一批 `skill_identity` + `entry` |
| `fields` 自由文本 | `skill_field`（raw + value） |
| `data-marks` 逗号串 | `skill_mark` 多行 |
| `data-search` | `search_doc.text` |
| `skill_effects_*.json` | `skill_content_block` + 后续 handler |
| 同名合并 | 两个 identity + 各自 entry |
