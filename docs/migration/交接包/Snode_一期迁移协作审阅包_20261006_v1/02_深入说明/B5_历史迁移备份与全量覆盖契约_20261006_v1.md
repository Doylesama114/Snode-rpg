## 分层读取与显式记录选择

读取容器、捕获来源事实、领域标准化、服务预览和授权提交分层。OOXML关系、共享／内联字符串、转义、稀疏单元格、合并、字体颜色、公式与缓存属于读取层；职业绑定、UID、成长、栏位和规则属于领域层，数据库／资产属于服务层。

选择维度是文件中的保存条目、工作表、实体区域及槽位。一个表可以混有多个角色、规划或参考资料，不能把最大表／第一个表／所有非空格合并成一个角色。同等候选先确认；已确认的支持表保留为supporting-data，不能串入主实体属性。

源事实有稳定sourceFactId、locator、raw与样式语义；空、0、负值、错误缓存和未提供分别处理。公式缓存是当时的事实快照，缺缓存不等于0，读取不执行未知公式或外部工作簿；需要规则计算时另按确认模型。单条旧saves字符串损坏可以保留该条问题并查看其他条目，整个JSON／ZIP损坏则不能伪报成功。

多槽位不自动成为多个正式角色。用户选择当前候选，其余作为历史依据／待导入记录，不把它们套用当前角色的正式命令历史或用于重复发放资产。文件名称和charCount不能决定真实人数、身份或覆盖目标。

## 元数据版本、可见编辑与UID

现有reader接受metaVersion 1至3，writer明确写3。B5支持清单包含1／2／3适配及无meta路径；高于已支持版本、坏JSON、重复UID或缺必需列返回明确问题，可见原文仍可保存为待核对依据，不能忽略错误然后声明已完整恢复。

| 元数据与可见内容 | 处理 |
| --- | --- |
| 基线一致、实体身份明确 | 恢复额外来源／选择／UID及元信息，技能和天赋走同一身份协议 |
| 修改备注等但仍为同一条目 | 显式识别可修改字段并保留原UID；未确认来源不覆盖新输入 |
| 同名／改名／换技能导致身份不明确 | 列候选及原基线，用户确认编辑原条目还是替换；不只凭姓名继承UID |
| 删除行／空格／消失的已写条目 | 区分删除意图、模板移动和损坏；云角色永久移除要走B4确认，不用文件缺字段自动遗忘 |
| writtenToVisible=0的溢出或未定栏位条目 | 保留且展示；不因表格容量不足消失，也不自动变成合法活跃能力 |
| 无UID的旧格式 | 首次分配候选与正式映射并留依据，重试沿用；不是每次读入按数组位置／名字随机生成 |

metadata中的服务器身份、权限、余额或‘validated’不是授权。正常同角色保存／新备份往返保持实例ID；显式复制产生新身份映射，内部引用同步转换，原UID作为来源证据。角色范围内完整实例引用用characterId＋uid，独立持久单位／资产另有服务身份，不混为一套全局名字键。

## 解析未知来源与补全

未知能力、职业来源、初始风格、学习途径、选择、占栏、成长依据及原有效数值均保留。别名与相似名字只能提供候选；旧skillId重号按来源系统／表／版本匹配，不能取第一项或默认主职业。规则目录更新不在读取时静默改旧角色绑定发布。

来源补全按issueId与candidateUid，显示Entry的职业、表、阶位、风格与完整正文。服务更新对应能力、获取、成长／关键属性、placement及栏位关联，保持现实例UID；不是重新学，不扣一次新费用、不重领旧收益。若导致栏位超额、同名禁学或派生条件变化，先预览处理，不能自动删其他条目腾位。

历史属性／最大HP来源不全时保留记录事实和问题，不猜哪项已包含奖励；缺初始或升级事实不默认从1级重算。角色资料可先保存，但自报XP／技能点／等级的导入声明不等于可信可消费的成长权益；操作所需来源仍核对，相关自动成长保持依赖阻塞。

## 资产待核对与主持人入账

| 层次 | 可做的事 | 权威边界 |
| --- | --- | --- |
| 原始资产声称 | 保留金币单位、数值、物品说明、数量／布局及源记录；在面板单独展示 | 未批准不进钱包／库存、不成为权威equippedAssetLinks或自动装备加成 |
| 已存在的新平台资产引用 | 服务检查当前所有权、版本和目标，在合法范围关联 | 文件assetId／旧余额不直接授权，副本不能与旧角色共同拥有同一实例 |
| 入团DM审批 | 审核明确claimSet及版本、选定claimIds、单位／物品匹配、数量、接收角色和decision | 当前同团资格及审批cap由3.2验证；审批不能成为无限余额setter |
| 正式入账 | 角色、资产、源映射、防重领取／审批回执、审计及角色修订共同事务保存 | 同源资产不得在多次文件更新／复制中重复入账，批准后仍按当前团权限交易 |
| 拒绝／未批准／原文修改 | 声称及裁定保留，新输入改变claim版本后重新审核 | 旧decision不适用于已换金额／物品的声称，拒绝不抹掉原件 |

未入团无法由团DM确认，声称保持pending。B3按合法建卡规则生成的起始资产是另一条可信来源，不因B5声称审批把它与历史迁入重复授予。已有云角色的导入不会覆盖资产余额；同平台备份引用能从当前服务核实的既有资产，不需要把旧快照再发一遍。

文件Hash只标源字节，不证明真实性或所有权，也不是唯一去重键。服务保留来源实体／槽位／行映射和importLineage；不同Hash可能是同一原角色新版本，相同Hash也可能有多个记录。旧格式没有稳定原ID时由用户显式关联来源，不按同名强行合并；审批按可信来源关联和已入账实例再核对。

## 新JSON备份与XLSX恢复范围

新版NativeBackup具有kind和formatVersion，保存完整CharacterDocument、出处与修订、资产声称／引用、付款／领取陈述和preservedFacts。语义备份必须保留来源、UID、选择、原文、未决问题、人工调整及永久限制，不能只导出ManagementView或可见技能表。

出处、Hash和不可逆陈述用于核对，不是可伪造的登录／授权凭证；不导出会话、令牌、拥有者权限或可直接执行脚本。更新现角色明确目标及当前revision，保留当前永久禁学、支付／领取、固定时间线和经济事实；新建遗留角色不重放创建／升级。普通恢复和导入都不能用旧高余额退款或把禁学空表覆盖回去。

导出取同一人物版本的授权字段，资产注明各自抓取版本／时间；它们不能被混成同一权威revision。原始来源附件若不随文件嵌入或另有正式受控包，明确其未保留范围，不用本机绝对路径冒充可跨设备恢复附件。JSON是角色语义备份，不承诺恢复任意工作簿的宏、图表、美术或第三方公式环境。

XLSX导出以已支持模板／映射为前提，提供可见值、技能／天赋／图纸及溢出条目的展示，元数据携带可恢复来源和UID。缺meta或被第三方删除／改写后，只保证实际剩下的可见内容；必须报告损失范围，不能叫无损。元数据有基线和校验关联，损坏、移动、手改、删除、替换和不同O／R天赋列都进入测试矩阵。

读取或生成失败不报告成功。浏览器能触发下载不等于文件已存盘；提示区分文件已生成／已发起下载与可核实的保存成功。重复导出不改角色、不重发奖励，正式三次导出导入验收必须经过新平台真实转换和读取，不能只对同一JSON stringify／parse作完成证明。

角色导入以受限SourceDescriptor、明确RecordSelection、capturedFacts、来源映射、固定规则和target模式提交。new-legacy／update-existing／explicit-copy分Schema；更新必须expectedRevision，复制／新建不信任文件characterId、owner或团声明，也不借新ID绕过已有时间线约束。

预览返回输入／转换版本、选定记录、待核对项、差异、资产pending状态及语义planHash。提交再验证来源、权限和当前数据，角色／映射／问题／历史／命令结果同事务；资产入账是固定声称版本的独立授权审批，不伪造‘角色已经存入所以资产已成功’。

命令登记、pending恢复和当前授权回放沿用B2。原命令同键重试；用户改映射／目标用新命令，服务仍按来源物化、不可逆事实和资产入账关联防重。入团或未知结果变化后，不把旧预览和旧审批当成当前权限。
