## 统一术语与权威边界

| 统一名称 | 旧称或易混概念 | 当前约定 |
| --- | --- | --- |
| CharacterDocument | CharacterData／整份角色JSON | 角色选择、进度、获取、资源、来源和迁移事实；不是账号权限或库存权威 |
| CharacterRecord及服务元数据 | 角色文档身份区／本机存储行 | ownerUserId、修订、时间线／团、生命周期及系统时间由服务持有；T07候选尚需补生产归属结构 |
| ClassProgression | ClassAssignment／职业人物class | 角色内进度UID，role与baseClass分开；新增职业或人物不新增程序子类 |
| AbilityEntry | AbilityListEntry／只按技能名绑定 | 具体来源、表、阶位、风格与获取规则；正文可以共用，获取上下文不能合并 |
| RuleReleaseRef | rulesetVersion／rulesetReleaseId | 领域引用是id＋manifestHash；数据库可有登记ID；旧参数名不自动成为正式HTTP契约 |
| ManagementView v1 | 角色表结构／全量备份 | 完整文档的授权只读投影；严格字段不随意扩展 |
| RecordAssessment | validated上传标记／新的生命周期值 | 服务读取评估与操作阻塞范围；保存成功不等于规则校验完毕 |
| DerivedActorSnapshot | CombatSnapshot／ActorSnapshot | 未来战斗快照方向，消费角色修订与资料版本；本轮不冻结全部战斗字段 |

3.1负责所需前后端、资料及规则解释；3.2提供身份、权限、持久化和资产基础。共享包与数据库在现有contracts／db入口共同协作，具体操作只有一个提交编排入口。规范发布包是资料读取权威；钱包／库存是资产服务权威；本机草稿是恢复输入，均不能反向覆盖另一方权威。

| 发现 | 具体处理 | 关闭边界 |
| --- | --- | --- |
| G01 正文混用CharacterData、ClassAssignment、CombatSnapshot和rulesetVersion等早期称呼 | 规范名称统一并列旧名映射；历史调查来源保留，不当成第二套模型 | 文档直接修正；不改T07原类型 |

| G03 T07 CharacterRecord尚未声明ownerUserId，而服务设计必须保存归属 | 在可信服务元数据增加归属字段，保持账户权限在领域文档之外；示例仅展示服务形状 | D03／D05／D11；不凭文件owner字段授权 |
| G04 现有管理v1严格拒绝额外字段，不能直接加入quality、issues或新操作payload | 新命令和Workspace包装DTO独立版本；管理三字段回执与五字段命令不变 | D04／D05 |
| G05 本机未保存选择没有服务ChoiceRecord ID | HTTP提交ChoiceSubmission／ChoiceUse；服务生成记录后向内层规则传正式ID | D06；已提出解决方案，尚未实现 |
| G06 字符串预算与标准Schema maxLength的Unicode计数不同 | UTF-16预算单独同源检查；34例含非BMP字符；预算计量变更另做兼容说明 | D12；软件限制，不是游戏规则 |
| G07 新增待核对与未入团政策需要与正式建卡／生命周期区分 | 新建缺选择仍为本机草稿；历史未知可正式保留；quality是服务评估；未入团元数据允许null，首绑时间线固定 | 产品已确认；服务约束仍由D09／D11落实 |
| G08 HP／FP直接编辑与来源池／状态的汇总写入有不同语义 | 首轮只提升可定位普通字段；临时生命、护盾、力竭按来源UID操作；XP／技能点／成长不开放任意数值写 | D04；避免聚合值覆盖已有来源 |
| G09 资产、历史恢复和导入都可能重复授予或回写旧余额 | 共同事务、幂等与迁移关联；快照用于角色历史，资产按当前归属复核 | D07／D08／D09；无资产授权不能报完整迁入 |
| G10 完整战斗、休息使用次数自动恢复和全格式迁移尚未验证 | 一期先保证手工状态及约定范围；自动休息／次数持久化在该功能前补模型；真实JSON／XLSX及全资料另按批次验收 | 后续功能缺口保留，不假装已实现，也不作为B1架构前置 |
| G11 领域已有paymentIds、operationId等关联，但支付／授予／领取回执的存储归属与防重键尚未正式约定 | 把操作、支付、授予与资产流水的关联纳入D03／D06／D07；服务生成可信记录，历史缺依据不伪造付款或领取证明 | B3／B4成本和奖励操作前落实；不阻止公开目录 |

这里区分已能通过文档统一解决的歧义、已有具体方案但待共同确认的接口问题，以及实现阶段才验证的覆盖缺口。不能因为有一个未定技能或旧表就阻止公开全文迁移；需要执行该规则的具体操作，才按依赖标记阻塞。完整运行时角色Schema、授权和资产事务是生产保存门槛，九项最小示例不能替代它们。

## 可检验的最小Schema评审候选

本轮提供[九项最小Schema候选](../01_计划与设计材料/迁移最小共享Schema_评审候选_20261006_v1.json)与[34个评审样例](../01_计划与设计材料/迁移最小共享Schema_评审样例_20261006_v1.json)。它们放在旧仓库docs/migration作为设计材料，未加入目标packages/contracts或业务运行链。

| 形状 | 可评审重点 | 还须另做的校验 |
| --- | --- | --- |
| DefinitionRef／RuleReleaseRef | 精确身份、正修订、发布绑定 | 引用是否存在、kind是否匹配、manifest是否属于指定发布 |
| ChoiceValue／ChoiceSubmission／ChoiceUse | 受控选择值；已保存ID与本次临时键区分 | 选择数量／范围、互斥、引用归属、重复键和正式UID生成 |
| ManagementView | 严格v1字段、负HP／0／null、明确editable与生命周期 | 字段授权、fieldRef唯一、有限数值和文本预算 |
| UpdateManagementCommand | 五字段命令头，profile／set-number／clear-number；多余字段拒绝 | 登记写字段、重复目标、当前权限、expectedRevision和幂等 |
| CommitReceipt | commandId、submittedDraftVersion、view三字段关联 | 是否是当前会话／当前冻结命令；不采纳旧回执 |
| CharacterServiceMetadata | 服务owner、修订及空／已绑定团关系的最小结构 | 归属来自真实登录；首次绑定后固定时间线；单团约束和授权 |

候选含17个定义块，9个对外评审形状。使用目标已有Ajv2020依赖核验，没有安装新库；Schema合法并可编译，34例预期全部匹配：18个结构通过、16个结构拒绝。另有5个结构能通过但必须被基础语义检查拒绝的例子，覆盖重复编辑／字段、未登记写字段和UTF-16预算差异。测试未验证游戏合法性、真实目录关系、账号权限、API或数据库。

文本预算暂沿用当前候选ID 128、名称256、故事65536个UTF-16代码单元；这些是软件限制，尚待D12确认。Schema的字符串长度计数不能直接代替现有JavaScript string.length预算，因此本候选单列同源后置预算检查，保留输入且不截断。JSON数值解析后还需有限数值校验；预算、字段唯一、登记白名单与结构Schema分开验证。

这份包不是完整CharacterDocument Schema，也不覆盖全部资料正文、建卡、成长和资产命令。结构验证、关系验证、游戏规则和授权是四个独立层次；不能给未解析角色payload加一个任意字典，然后宣称完整Schema已完成。正式实现时由共同结构生成／推导TS和接口校验，避免再次手工维护不一致的定义。

## 分批开工和验收门槛

B0按各批真正需要的D决定分项评审，不要求一口气先定转团、云草稿和全部技能。下面是技术准备门槛，仍需遵守用户当前只做设计的安排，不自动授权开始代码。

| 批次 | 该批必须先定 | 不必等待与验收依据 |
| --- | --- | --- |
| B1 | D01、D02、D12；首个目录／查询／完整详情切片；其资料结构、引用、发布与运行时Schema | 不等：账号、云草稿、全部角色Schema或完整战斗；验收：正文与关联单位覆盖、版本引用一致、公开访问及错误版本检查 |
| B2 | D01、D03、D04、D05、D07、D10、D11、D12；真实登录保存与读取、完整文档Schema／适配、服务owner／权限、事务回执与本机恢复 | 不等：全职业技能自动化、云草稿、转团及全部经济玩法；验收：数据库重开、已保存版本跨设备、并发／超时／授权、无效字段保留 |
| B3 | D06、D08；首个支持建卡组合的完整选择、固定规则包、起始授予和资产统一事务；另依赖B1／B2 | 不等：全部建卡分支或所有技能效果；验收：合法性、收益仅一次、资产失败回滚、冻结命令恢复 |
| B4 | D04、D06、D07、D08；升级学习、授予与放弃、装备、来源池／状态和历史恢复的明确支持范围 | 不等：完整战斗引擎；未定费用只阻止相关自动操作；验收：UID／来源／栏位／限制、三方冲突、资产当前归属和历史不可逆项 |
| B5 | D02、D06、D08、D09；全公布资料与建卡管理分支、真实旧档迁移、新版JSON及约定XLSX往返 | 不等：全部内容可自动战斗；验收：全量清单、真实档案、多表／多槽、未知保留、UID及资产去重 |
