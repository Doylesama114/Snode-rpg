### F4 收敛记录（2026-10-24）

F4 原申请 8 个引擎，按「同机制只立一个」原则收敛为 2 个：

| 原申请 | 去向 |
| --- | --- |
| 情报揭示 | → **E39**（吸收 E12、定位、感知、只读型沟通） |
| 双向通信 | → **E57**（独立成引擎：有成员集合与退出条件） |
| 判定封锁 | → E14 `forbidCheck/blockCheck` + advantage 取最低档 |
| 专注改写 | → E03 payload `concentration` |
| 次数复原 | → E05 `resource='uses'` |
| 随机条目解锁 | → E19 增 `pool/count/reveal`（改的是知识条目可见性，不是物品） |

F4 的 ⚠ 从 6 降到 4，参数条目 18 条。它还提出一个口径问题：
**复用率该按「技能条数」算还是按「引擎步数」算**——按条数算，那 15 条纯信息技能天然没有战斗结算可挂。

## 五、判断说明

用户明确「大胆扩建、法师可作标杆」，故不设数量上限。但归并时仍执行三条：
1. **同一机制只立一个**（光照、地形、关键词三处跨批重复已合并）
2. **能降级为参数的不立引擎**（6 项降级）
3. **专属引擎单独标注**（E53 法术序列、E56 建筑部署），便于后续判断是否值得通用化

其中 **E40 召唤物属性块**是最关键的一个：法师 69 条含召唤，且原文里 3 条召唤物的属性块**根本不存在**（#091/#093/#094），
这条引擎直接决定「召唤」这一大类能否落地。
