# 技能数据：数据契约与数据库 schema（设计说明 · 2026-10-24）

> 目的：把已经拆分好的 497 条结构化技能，变成**可存储、可查询、可展示**的资料库。
> 这是 3.1.1「实现资料展示、搜索与查询」的第一步。

## 一、两个东西分别是什么

| | 数据契约（Contracts） | 数据库 Schema |
| --- | --- | --- |
| 位置 | `packages/contracts` | `packages/db/src/schema.ts` |
| 是什么 | 前后端共享的 **TypeScript 类型** | **PostgreSQL 表结构**（Drizzle 定义） |
| 管什么 | API 收发的**形状** | 数据**怎么存** |
| 改了会怎样 | 两端编译期就报错 | 需要迁移（migration） |
| 现在有什么 | 11 行，只有 `HealthResponse` / `ReadinessResponse` | 9 行，只有 `users` 一张表 |

**为什么两个都要**：没有契约，前端写 `damageDice`、后端返 `damage_dice`，只有跑起来才发现；
没有 schema，497 条数据只能躺在 markdown 里，查不了、搜不了。

## 二、技能数据的特殊性（决定设计）

| 特征 | 数据现实 | 对设计的影响 |
| --- | --- | --- |
| 一半结构化 | 施展时间/距离/持续/疲劳/关键词，全是固定字段 | 用**列**存，可索引 |
| 一半极异构 | 65 个引擎，每个参数都不同（`E01` 有伤害骰、`E08` 有模板、`E30` 有修正目标） | 效果步骤用 **JSONB**，不拆表 |
| 原文必须保留 | 要展示、要追溯、要给人读 | 原文用 **text** 列并存 |
| 有成长覆盖 | 251/422 条含「N 级时改什么」 | `growth` 也用 JSONB |
| 有跨技能引用 | 34 条引用别的能力 | 单独的**引用表**，建依赖图 |
| 有同名 | 18 组同名（不同职业/领域） | 唯一键是 `(来源文档, 名称)`，不是名称 |
| 有完成度 | 现在 22% 已拆分 | `status` 列区分 待拆分/草稿/定稿/待补 |

## 三、数据库 schema 设计

### 3.1 主表 `skills`

```ts
export const skills = pgTable("skills", {
  id: uuid("id").defaultRandom().primaryKey(),
  // 身份
  sourceDoc: text("source_doc").notNull(),        // '基础职业-法师.docx'
  name: text("name").notNull(),                  // '背刺'
  slug: text("slug").notNull(),                  // 'rogue-backstab'，给 URL 用
  form: text("form").notNull(),                  // 'skill' | 'talent'
  classSlug: text("class_slug"),                  // 'rogue' | null（领域条目）
  style: text("style"),                          // '暗影风格'
  tier: text("tier"),                            // '一阶天赋树'

  // 施展段（全是定值，用列）
  actionCost: text("action_cost"),                // 'main' | 'bonus' | 'reaction' | 'none'
  rangeText: text("range_text"),                  // 原文，'6米'
  durationText: text("duration_text"),
  fatigueCost: text("fatigue_cost"),              // '1' | '1D3'（有骰式，故用 text）
  usesText: text("uses_text"),                    // '短休/长休(2)'
  uniqueKey: text("unique_key"),                  // 唯一性技能的 key

  // 内容
  rawText: text("raw_text").notNull(),            // 原文描述（含召唤物数据块）
  effects: jsonb("effects").$type<EffectStep[]>(), // 步骤序列
  growth: jsonb("growth").$type<GrowthRule[]>(),
  limitations: text("limitations"),

  // 元数据
  status: text("status").notNull().default("todo"), // todo|draft|final|blocked
  coverage: text("coverage"),                     // clean|partial|blocked
  flags: jsonb("flags"),                          // { hasSummon: true, hasRing: false, ... }
  createdAt: timestamp("created_at", { withTimezone: true }).defaultNow().notNull(),
  updatedAt: timestamp("updated_at", { withTimezone: true }).defaultNow().notNull(),
}, (t) => [
  uniqueIndex("skills_source_name_idx").on(t.sourceDoc, t.name),
  index("skills_class_idx").on(t.classSlug),
  index("skills_status_idx").on(t.status),
  index("skills_slug_idx").on(t.slug),
]);
```

### 3.2 关键词表（五维度检索的基础）

```ts
export const skillKeywords = pgTable("skill_keywords", {
  id: uuid("id").defaultRandom().primaryKey(),
  skillId: uuid("skill_id").notNull().references(() => skills.id, { onDelete: "cascade" }),
  category: text("category").notNull(),  // '技能与天赋' | '攻击类型' | '能力类型' | '元素属性' | '机制标签' | '效果标签' | '特殊标签'
  value: text("value").notNull(),        // '战技' | '近战攻击' | '位移' …
}, (t) => [
  index("sk_category_value_idx").on(t.category, t.value),
  uniqueIndex("sk_unique_idx").on(t.skillId, t.category, t.value),
]);
```

**为什么不存成 `text[]`**：要按「机制标签=位移」筛，还要统计「每个标签有多少技能」，关联表能直接 `GROUP BY`。

### 3.3 引擎字典

```ts
export const engines = pgTable("engines", {
  code: text("code").primaryKey(),        // 'E01' … 'E68'
  name: text("name").notNull(),           // '伤害结算'
  scope: text("scope").notNull(),         // 'ability' | 'subsystem'
  params: jsonb("params"),                // 参数签名
  reuseNote: text("reuse_note"),          // 复用面
  isUniversal: boolean("is_universal").notNull().default(true),
});
```

这张表是**给开发者看的**：查某个引擎被哪些技能用了、参数长什么样。

### 3.4 引用关系表（能力引用 / 依赖图）

```ts
export const skillRefs = pgTable("skill_refs", {
  id: uuid("id").defaultRandom().primaryKey(),
  fromSkillId: uuid("from_skill_id").notNull().references(() => skills.id),
  toKeyword: text("to_keyword"),          // '战技'
  toName: text("to_name").notNull(),      // '毒刃'
  resolvedToId: uuid("resolved_to_id").references(() => skills.id),
  status: text("status").notNull(),       // 'resolved' | 'ambiguous' | 'unresolved'
});
```

对应决策 D97：引用解析三态。这张表让「删除一个技能时，谁受影响」变成一次查询。

## 四、数据契约设计（TS 类型）

```ts
// packages/contracts/src/skill.ts

export type SkillForm = "skill" | "talent";
export type SkillStatus = "todo" | "draft" | "final" | "blocked";

/** 列表页用：轻量，不返回 effects */
export interface SkillSummary {
  id: string;
  slug: string;
  name: string;
  form: SkillForm;
  classSlug: string | null;
  style: string | null;
  tier: string | null;
  actionCost: string | null;
  keywords: { category: string; value: string }[];
  status: SkillStatus;
}

/** 详情页用：完整 */
export interface SkillDetail extends SkillSummary {
  rawText: string;
  rangeText: string | null;
  durationText: string | null;
  fatigueCost: string | null;
  usesText: string | null;
  effects: EffectStep[] | null;
  growth: GrowthRule[] | null;
  refs: SkillRef[];
  sourceDoc: string;
}

export interface SkillQuery {
  q?: string;                    // 全文检索
  className?: string;
  form?: SkillForm;
  keyword?: string[];            // 多维筛选，AND 关系
  actionCost?: string;
  status?: SkillStatus;
  page?: number;
  pageSize?: number;
}

export interface SkillListResponse {
  items: SkillSummary[];
  total: number;
  page: number;
  pageSize: number;
}
```

**契约的价值**：前端 `const { items } = await fetchSkills({ keyword: ['位移'] })`，
`items[0].keywords` 的形状由契约保证，改了字段两边立刻编译报错。

## 五、效果步骤怎么存：JSONB 而不是拆表

```ts
export type EffectStep = {
  engine: string;                 // 'E01'
  params: Record<string, unknown>;
  timing?: "before" | "after" | "onHit";
  condition?: string;             // 表达式文本
  out?: string;                   // 产出变量名
  owner?: "self" | "target" | "summon";
  growth?: Record<string, Partial<EffectStep>>;
};
```

**理由**：65 个引擎的参数完全不同。如果拆成「参数表」，就会变成 EAV（实体-属性-值）模式，
查一个技能的完整效果要 join 几十行，且没有任何类型保障。

**代价与补救**：JSONB 不能按「伤害骰」这类字段直接建索引。补救措施：
1. 把 `engine` 抽成生成列 + B-tree 索引 → 能查「哪些技能用了 E01」
2. `effects` 建 GIN 索引 → 能查「包含某个关键词的步骤」
3. 高频检索字段（伤害类型、是否有召唤）提成 `flags` 列

```sql

source_doc = '基础职业-游荡者.docx'

form        = 'skill'

tier        = '一阶天赋树'
action_cost = 'main'

  {"engine":"E13b","params":{"sector":"背面"},"out":"isBehind"},
  {"engine":"E01","params":{"hitBonus":"+2*isBehind","post":"+1D4"},
   "growth":{"3":{"params":{"post":"+2D4"}},"6":{"params":{"post":"+3D4"}}}}
]
status      = 'final'

-- skill_keywords 行（每维度一行）
('技能与天赋','技能') ('攻击类型','近战攻击') ('能力类型','战技')
('机制标签','位移')  ← 若无则不插

-- 查询「所有带位移机制的近战战技」
SELECT s.name FROM skills s
JOIN skill_keywords k ON k.skill_id = s.id
WHERE k.category='机制标签' AND k.value='位移'
  AND EXISTS (SELECT 1 FROM skill_keywords k2
              WHERE k2.skill_id=s.id AND k2.category='能力类型' AND k2.value='战技');
```

## 七、检索怎么实现（3.1.1 的「搜索与查询」）

| 需求 | 方案 |
| --- | --- |
| 按名称搜 | `ILIKE '%关键词%'` + 索引，最简单 |
| 按原文全文搜 | PostgreSQL `tsvector` + GIN（中文需 `pg_jieba` 或先分词） |
| 按维度筛（机制/元素/能力类型） | `skill_keywords` 关联查询 |
| 组合筛选 | 动态拼 WHERE，参数化 |
| 排序 | 相关度（全文）或 名称/阶位（浏览） |

**中文全文检索要注意**：Postgres 自带的分词不支持中文。
三个选项：① 装 `pg_jieba` 扩展 ② 用 `pg_trgm` 做三元组模糊匹配（对短词够用）③ 先分词再存 `tsvector`。
我倾向 **② pg_trgm**——技能名和关键词都很短，模糊匹配够用，且不用额外扩展依赖。
