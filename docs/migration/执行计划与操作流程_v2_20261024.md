# 执行计划与操作流程 v2（2026-10-24）

> 取代 `计划_20261024_修订版.md` 中的执行部分。变化原因：P0 试点暴露模型缺口、子代理复核证明交叉验证必要、
> 且单职业一次写完的方式不适合反复答疑。

## 一、相对上一版改了什么

| 项 | 上一版 | 本版 |
| --- | --- | --- |
| 拆分方式 | 一个人一次写完一个职业 | **每职业一轮：拆 → 复核 → 汇总 → 答疑 → 定稿** |
| 复核 | 无 | **固定派 4 个子代理独立重写 + 对账** |
| 施展段 | 人工填写 | **机器生成，禁止人工抄写**（D99） |
| 问题处理 | 边写边问 | **先汇总，每职业跑完一轮统一上报答疑** |
| 模型演进 | 遇缺口临时加 | **缺口归类后成批修订，避免逐条打补丁** |

## 二、操作流程（SOP，每职业执行一轮）

### 阶段 0 · 准备（机器，零人工）

| 步骤 | 产出 |
| --- | --- |
| 1 | `<职业>_技能全文.md`：从 survey JSON 导出全部条目原文，不截断 |
| 2 | `<职业>_施展段表.md`：施展时间/距离/持续/疲劳/次数/修饰六列，**直接从结构化字段抽取** |
| 3 | 按编号均分 4 批，准备子代理任务书 |

### 阶段 1 · 拆分（4 个子代理并行）

- 每个子代理：读任务说明 → 读模型规范 → 读自己那批全文 → 写效果步骤序列
- **施展段不重写**，直接引用阶段 0 生成的表
- 铁律：必须读描述原文；不猜实现；读不出写 ⚠ 并说明缺什么

### 阶段 2 · 复核与对账（我）

- 合并 4 批成《步骤序列表》
- 与上一轮（若有）逐条对比，差异单列
- 缺口按四类归档（见阶段 3）

### 阶段 3 · 汇总问题（产出《<职业>问题清单》）

问题只分四类，不混在一起：

| 类别 | 含义 | 由谁解决 |
| --- | --- | --- |
| A 新增引擎申请 | 现有引擎无法承载，需新增 | 用户批准 |
| B 参数补齐 | 引擎对，但参数不够 | 我改规范 |
| C 原文缺定义 | 文档没写清，需要主持人 | 用户转达 |
| D 语义分歧 | 两种解释都通，需拍板 | 用户 |

### 阶段 4 · 上报答疑（用户）

- 每职业跑完**一轮**统一上报，不边写边问
- 报告含：覆盖率、四类问题数量、A/C/D 类逐条

### 阶段 5 · 修订与重跑

- A 类批准后进模型（v4/v5…）
- B 类我直接补参数
- 重跑受影响的条目，不重跑全批

### 阶段 6 · 定稿

- 写入 `P1_<职业>_步骤序列.md`，标注每条覆盖率状态
- 记录本职业新增引擎数

### 阶段 7 · 清理

- 作废的中间脚本/实例 → `lab/回收区/YYYY-MM-DD/`
- `_scratch/` 只留结论性数据

## 三、每职业固定产出（5 份）

```
docs/migration/<职业>/
├── 01_技能全文.md          机器生成
├── 02_施展段表.md          机器生成
├── 03_步骤序列.md          定稿（合并 4 批）
├── 04_问题清单.md          上报用
└── 05_覆盖率报告.md        数字 + 缺口分类
```

## 四、质量门（每职业必过）

| # | 门 | 不通过怎么办 |
| ---: | --- | --- |
| 1 | 施展段 100% 机器生成，人工填写数为 0 | 重跑生成脚本 |
| 2 | 每条步骤能对应到描述原文片段 | 补出处，补不了说明是猜的，删掉重读 |
| 3 | ⚠ 率 < 30% | 说明模型不够，先修模型 |
| 4 | 本职业新增引擎申请 ≤ 3 | 超过则停线复盘，不铺下一个职业 |
| 5 | 覆盖率 ≥ 70% | 同上 |
