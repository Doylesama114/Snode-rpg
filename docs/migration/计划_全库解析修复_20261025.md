## 二、根因

docx 里一条技能的内容被拆在多个单元格，而其中有**没有字段标签的延续单元格**。
原解析器只收「字段名：」格式的单元格，于是这些块被丢弃。

## 四、关键设计：三类内容分开存

**不能把延续单元格一股脑塞进描述。**否则配方材料会混进效果描述，搜索时会误命中。

```
描述        ← 技能效果正文（含召唤物属性块）
配方材料     ← 单独字段
物品属性     ← 单独字段（价格/负重/类别/使用限制）
```

判定规则：延续单元格若以「配方材料：」「使用限制：」「参考价格：」等开头，归入对应字段；否则并入描述。

## 六、风险与对策

| 风险 | 对策 |
| --- | --- |
| 延续单元格吞掉下一个技能的字段 | 边界判定：下一个技能名 + 其后紧跟字段名 |
| 配方材料混入描述 | 按前缀分类，不并入描述 |
| 误改原本正确的条目 | 差异必须为空才算通过（标准 3） |
| 与已有拆分结论冲突 | 只修数据，不动拆分；受影响条目**单独列清单**，不自动重做 |
