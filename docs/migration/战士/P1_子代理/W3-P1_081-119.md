## 记法

| 记法 | 含义 |
| --- | --- |
| `E..(参数=值;…)` | 一个效果步骤 |
| `→` | 结算顺序 |
| `?条件` / `?save=失败` | 该步骤（或分支）的执行条件 |
| `x{…}` | 表达式（引用运行时变量） |
| `out=…` | 步骤产出变量 |
| `@前 / @后 / @命中 / @未命中 / @轮末` | 时机（before-damage / after-damage / on-hit / on-miss / turn-end） |
| `〔N级:…〕` | 等级成长覆盖 |
| `†Bn` | B 类参数补齐（不阻断落值） |
| `†Cn` | C 类原文瑕疵或缺定义（已按口径占位） |
| `⚠n` | 阻断项（见 ①） |

## ⑤ 模型对不上的地方（验证轮结论）

> 本轮主要交付。按"模型层"排，原文缺口在 ① 的 C 类。

### 1. `TargetRef` 缺「群体」这一档 —— 已到非补不可的程度

`TargetRef` 现有 7 个值（self / original / area / selected / summon / holder / source）全是"单点或区域"，没有"编队/群体"。#091 阵列推进的**每一个**步骤都要指向「阵列成员」，并要能判定「谁离阵」。用 `area` 近似 → 换不出「脱阵即解散」，也换不出「共享 AC 取阵列最高」（`area` 只能给区域内每个单位各自加值）。
**这不是参数问题，是引用类型缺一档** → `⟪W3-P1⟫-1`。

### 2. `cast.action` 枚举缺两档，且缺的都是战士的关键档

| 缺的档 | 原文证据 | 后果 |
| --- | --- | --- |
| **多动作**（2动作 = 主要+附赠） | #097 对军流星爆「施展时间：2动作」 | 只能硬塞 `main`，把"占两个动作"降级成注释 |
| **不占动作的主动施展**（instant） | #112 时速攻势「施展时间：（无）」+「疲劳消耗：4」+「你的下两次基础攻击具有速攻关键词」 | `none` 在模型里 = **纯被动**（无施展段），这里却是"主动声明、付 4 疲劳、不占动作"。v3.1 给了 `priority:'速攻'` 作动作**属性**，却没给"不占动作"的动作**槽** |

这条对战技系职业影响面很大（速攻 / 即时自增益是战士的高频设计）。

### 3. `E17.event` 的时点空白集中在「开场」与「未命中」两端

v3.1 + v4 一共补了 15 个事件，补的全是**中后段结算**。本批 6 条撞在两端：

| 缺的事件 | 撞上的技能 |
| --- | --- |
| `battle-start` / `initiative-rolled` | #089 战术掌握、#092 战场调度者、#095 战术优势 |
| `ability-miss`（自己施展的战技未命中） | #084 兵者诡道 |
| `own-attack-miss`（目标自己的攻击未命中） | #087 挫战怒吼 |
| `move-end` | #104 灵巧拾取 |
| `ranged-attack`（发起远程攻击时） | #109 一石二鸟 |

结论：**"战斗开始"这一类时点在模型里根本没有宿主**（也就解释了 #092 为什么只能靠 E09 硬凑）。

### 4. 「把强化补丁挂到别处定义的能力上」= 引用悬挂，不是引擎问题

三条同型：#095 的「战术」（12 个名字全库仅此一行）、#115 的「其他姿态」（战斗/防御/迅捷姿态在别的条目）、#096 的「军队级法术」（无列表）。模型侧（`E30` / `E43` / `E22` / `E21`）都能写补丁，**缺的是宿主**。按 v2.1 §2 走 `unresolved` + 保留原文，但执行器上**不可执行**。
→ 建议合并阶段把这三条并成一张「引用悬挂清单」，不要当三条孤立缺口。它也说明：**战士的"战术/风格"体系是跨条目引用的重灾区**（本批 39 条里 6 条靠 ref 成立：#078 #082 #093 #095 #115 #096）。

### 5. 百分比与资源上限是本批唯一的"数值层"缺口

- #117 的三档比例（50% / 10% / 5%）需要 `target.rank`（精英 / BOSS），模型没有这个变量；
- #086 / #087 的魂怒值、奋勇值**没有上限**（同书 #119 却明写"至多3个"）——这是**原文的不一致**，不是模型问题，但会直接卡住 `E05.cap`；
- #097「至少 1 层灼烧」的"至少"意味着有上限，原文没给。

### 6. 反过来说：模型在这批上是够用的

- **94.9%（37/39）** 条不需要任何新引擎；
- 唯一的搜索/推演型机制（#081「预演整个回合」）**E60 一击命中**，没有近似；
- 判断/徽记型机制（#113 #114 警戒、#110 摔绊、#108 飞网、#111 三段逆流）全部能用 E11 / E17 / E04 / E03 payload 组合落地；
- 已批准的 E34–E68 里有 **12 个**在本批被真正用上（E34/E37/E39/E43/E46/E47/E51/E52/E54/E57/E60/E67），说明法师批次的扩建对战士**有实际复用**，不是只为法师造的。
