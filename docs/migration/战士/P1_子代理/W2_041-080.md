> **范围**：#041–#080，共 **40 条**。逐条按 [01_技能全文.md](D:/Download/scholar-agent-main/docs/migration/战士/01_技能全文.md) 描述原文写，**只做这些编号**。
> **施展段不重写**：一律引用 [02_施展段表.md](D:/Download/scholar-agent-main/docs/migration/战士/02_施展段表.md) 第 041–080 行（机器生成）。仅当**等级成长改写施展段**时，在 〔〕 内注明 `cast.action` / `cast.range` / `cast.uses`。
> **引擎口径**：E01–E26 + E30–E33（30 个）＋ [法师/07_新引擎申请汇总.md](D:/Download/scholar-agent-main/docs/migration/法师/07_新引擎申请汇总.md) 已批准的 **E34–E68**（35 个，共 65 个），本批按**正式编号**直接引用（E36 关键词改写 / E38 场景屏障 / E41 施法变体 / E47 弹道拦截与偏转 / E51 印记与物件触发 / E67 能力转发）。
>
> **已确认口径（直接用，不报缺口）**
> - 1动作 = 主要、0动作 = 附赠、空白 = 纯被动。
> - **AOE 关键词隐含 DC15 敏捷豁免，成功仍受半伤**；原文「闪避成功」即指此。
> - **方形区域一律 `side=N 格`**：自身周围 X 米 → `side=2X+1`（周围 2 米 = 5×5，周围 4 米 = 9×9，周围 6 米 = 13×13）。本批 #076 周围 4 米 = `side=9`、#071 周围 6 米 = `side=13`、#049/#067 的「2*2」= `side=2`。
> - **N 环几何**（本批未使用，横排/正向按正面 3 格）。
> - 「失去生命值」= 跳过防御层但触发受伤（`E10.loseHp`）；「令生命值降至 0」= 直接改生命值、不触发受伤（`E10.setHp`）。
> - 「下一次 X 具优势」走 `E03 payload(grantAdvantage)`；唯一性走 `cast.modifiers=[{type:'unique',key:'技能名'}]`。
> - **伤害类型 33 种**照原文填；原文未写伤害类型的武器攻击一律写 `x{武器伤害类型}`（C 类，见 ①-C1）。
> - **护甲值的四条规则**（防御层顺序 / 心灵星界不可挡 / 钝击雷电力场邪能翻倍 / 穿刺挥砍剧毒减半）是 [速查表 §六](D:/Download/scholar-agent-main/docs/migration/技能拆分速查表_20261024.md) 的**全局规则**，不在每条技能里重抄；本批只在需要「铸造/清空护甲值」时写 `⟪护甲值⟫` 步。
>
> **记法**：`E..(参数=值;…)` 一个效果步骤；`→` 结算顺序；`?条件` 执行条件；`x{…}` 表达式；`out=` 产出变量；`〔N级:…〕` 等级成长覆盖；`†B` 参数补齐（不阻断落值）；`†C` 原文瑕疵/缺定义（不阻断落值）；`⚠` **执行器按现文得不出唯一结果**（见 ① 表）。
>
> **本批判定**：40 条中 37 条可完整表达；`†B` 参数缺口 14 处、`†C` 原文缺口 15 处、**⚠ 阻断 3 条**（#051 #056 #057）、**新引擎 0 个**。验证结论见文末 ⑤。

**判定过程（先怀疑模型不够，再确认其实够）**：本批 40 条逐条对照 E01–E26 / E30–E68 后，**没有任何一条需要一个新引擎**。三处最初看起来像缺引擎的，逐条验证后都能落到已有引擎＋参数：

## ⑤ 模型验证结论（本轮是验证轮，以下是我认为「对不上」的地方）

### 5.1 模型**扛住了**的部分（先说结论）

- **护甲值不是缺引擎**：v4 给 E05 的「自定义资源容器」+ E10 的 `armorValue`/`armorMultiplier` + 速查表 §六 的全局类型表，三者合起来已经把 #047/#050/#052/#057 覆盖完。**之前若有人把它报成 A 类，是误报。**
- **「阻止本次伤害」vs「减免」** 分得干净：#055 用 `abortDamage`、#041 用 `E30(incomingDamage,-5)`，两者不混。
- **「每场限一次 + 回合外需反应动作」** 这个复合限制（#068 #080）v4 的 `uses.onlyWhen + extraCost` 正好接住，不必新引擎。
- **关键词改写（E36）** 把 #059 的「第一次移动带迅捷」、#063 15级「升级为多重射击」这类**改的是关键词/身份**的东西接得很顺。

| **M3** | **表达式层没有聚合函数，逼出三处「参数打补丁」** | #062「目标周围4米内存在**两名**友方角色」、#078「军旗周围4米内存在**三名或以上**友方角色」、#045「回复**等量**但**不能超过15**」。D92 只有 `+ - * /`：数人头要 `count(area,filter)`，封顶要 `min/max`。现在只能靠 E30.clamp、E26.clamp 一个个补 | 表达式加 `count()`/`min()`/`max()`（B4）。**这是全库级**，不是战士特有 |
| **M4** | **「代受伤害」没有事件归属语义** | #043/#046/#056 都是「你代替对方承受一次伤害」。`E10.redirectTo` 只解决了**谁掉血**，没解决**「受到伤害」事件记在谁头上**。而 #045（受伤后回血）、#055（首次受伤阻止）、#041（首次受伤 -5）全部挂在这个事件上 —— **改一个 redirectTo 会静默改掉三条被动的触发**。这是模型里没有的一层（D1） | 在 E10 增 `damageEventOwner: 'receiver'｜'original'`，或在口径里钉死「代受 = 承受者既是掉血者也是受伤事件主体」 |

### 5.3 顺带发现的**口径不一致**（不是缺口，是文档问题）

1. **v4 §三 说「⚠ 只标执行器得不出唯一结果，A/B 类不占 ⚠」，但没人说 D 类占不占。** 本批把 #056（D2）、#051（C2）、#057（C3）都标了 ⚠，因为**执行器确实跑不出唯一结果**；若按「C/D 不占 ⚠」的口径，本批 ⚠ 应为 0。**建议把这条规则写死**，否则各批 ⚠ 率不可比（法师 03 号文件自己也说「34.6% 的 ⚠ 率不可采信」）。
2. **v3.2 §3 说「环」是全库级缺口统一进 Q19，但战士 41–80 一条「环」都没用到**（#053 的「横排（1）」是**正面 3 格的横排**，不是环）。若后续批次把「横排(1)」也当环报，是误报。
3. **#053 与 #038 旋风斩、#007 顺劈斩共用「我方正面横排」概念**，三处措辞不同（「前方横排（1）」「前方横排方向（1）」），建议统一为 `正面扇区 3 格` 一个术语。
