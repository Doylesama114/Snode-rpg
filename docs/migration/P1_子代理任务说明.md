## 记法

| 记法 | 含义 |
| --- | --- |
| `E01(…)` | 一个效果步骤，括号内为参数 |
| `→` | 步骤顺序 |
| `@前` / `@后` / `@命中` | 时机：伤害结算前 / 结算后 / 命中后 |
| `?条件` | 该步骤的执行条件 |
| `var=…` | 该步骤产出的变量 |
| `x{…}` | 表达式（引用运行时变量） |
| `ref:关键词.名称` | 能力引用 |
| `〔3级:…〕` | 等级成长覆盖 |

## 铁律（违反即为不合格）

1. **必须读描述原文**。禁止根据技能名或关键词推断效果。
2. **不猜实现**。读不出具体机制时，写 `⚠待确认：<你的疑问>`，不要编一个看起来合理的。
3. **一个技能可以拆成多个步骤**，这是常态。步骤按真实结算顺序排列。
4. 描述里有数字（DC、骰式、层数、持续）全部落到参数里；有表达式（2X、+5×点数）必须写成 `x{}`。
5. 只使用规范里已有的 26 个引擎编号；确实表达不了的，在待确认里写「需要什么能力」，**不要自造引擎编号**。

## 附加铁律（2026-10-24 增补，因出现断章取义）

### 6. 每个判断必须附原文引用

写任何一步之前，先在原文里找到**支撑这句话的那个句子**，把原句抄进你的工作笔记。
写不出原句支撑的步骤，就是你猜的——删掉重读。

### 7. 读到句号为止，不许中途下结论

实测事故：某技能写「每场战斗限一次.在自身回合外使用」——只读前半句就判「与递减-5 矛盾」，
实际后半句限定了范围，两者根本不矛盾。

**规矩**：一条描述必须读完整个自然段，特别是带「.」「；」的补充说明句，才能判定。
描述里出现「但」「仅」「除此之外」「在…情况下」等转折或限定词时，必须把那半句也读完。

### 8. 遇到「两个说法冲突」时，先怀疑自己没读全

顺序是：① 再读一遍原文 → ② 确认是不是没读到限定句 → ③ 确实冲突才上报。
报告冲突时必须写：**原文 A 句 = …；原文 B 句 = …；我判断冲突的理由 = …**
