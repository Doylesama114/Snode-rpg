# 技能效果步骤模型规范（2026-10-24 · v1）

> 服务对象：**② 战斗实现**（本期执行）。**③ 线上技能制作不在本期范围**，但本规范的所有结构均为数据驱动，
> 引擎自带注册表与参数签名，将来编辑器可直接读取，无需重构。
> 表达式范围（D92）：常量 + 运行时变量引用 + 四则运算。

## 一、技能的数据形态

```ts
interface Skill {
  id: string;                    // 稳定 ID，改名不变
  identity: {                    // ① 资料库层：人读
    classOrDomain: string;
    style: string;
    tier: string;
    form: 'skill' | 'talent' | 'recipe';
    name: string;
  };
  learn: {                       // 学习准入
    skillPoint: number;
    prerequisites: string[];     // 前置条件（人读文本 + 结构化可选）
    extraConditions: string[];
  };
  cast: {                        // 施展段
    action: 'main' | 'bonus' | 'reaction' | 'none';
    fatigue: Expr;               // 疲劳消耗，可为表达式
    range: Expr;                 // 距离（米）
    targeting: 'directed' | 'non-directed';
    duration: Expr;              // 持续时间；0 表示立即
    anchor: 'instant' | 'caster-turn' | 'target-turn';
    conditions: string[];        // 施展条件（如「必须处于潜行」）
    limits: string[];            // 施展限制
  };
  effects: EffectStep[];         // 核心：有序效果序列
}
```

## 二、效果步骤

```ts
interface EffectStep {
  engine: EngineId;              // 见第三节注册表
  params: Record<string, ParamValue>;
  target: TargetRef;             // 见第四节
  when: Timing;                  // 见第五节
  condition?: Expr;              // 满足才执行
  branch?: Branch;               // 分支
  growth?: GrowthOverride[];     // 等级成长覆盖
}

type ParamValue = number | string | DiceExpr | Expr | ParamValue[];
interface DiceExpr { dice: string }        // 如 { dice: '2D6' }
interface Expr { expr: string }            // 如 { expr: 'consumed.combo * 2' }

interface Branch {
  type: 'player-choose' | 'random';
  options: EffectStep[][];       // 每条分支自身又是一串有序步骤
  randomFrom?: string;           // 随机分支时的骰式
  selectCount?: Expr;            // 可选几条
}

interface GrowthOverride {
  level: number;
  patch: Partial<EffectStep>;    // 达到等级后覆盖的字段
}
```

# 附：v2 修订（2026-10-24 P0 试点后）

P0 试跑 10 条暴露 14 处缺口，据此修订。**修订原则：能用已有引擎组合出来的，一律不加新引擎。**

## 1. 「下一次施展修正」降级为状态（取消 E27）

用户提出的方案：**把「对下一次施展的修正」做成施加在角色自身上的状态，该状态在指定行动后自动消失。**

因此取消原计划的 E27，改为 **E03 能力扩展**：

```ts
interface StatusPayload {
  modifyScope: 'next-ability' | 'next-attack' | 'next-rest';
  modifyTarget: {
    filter?: { keyword?: string; name?: string };   // 如「带潜行限制的」「毒刃」
    patch: {                                      // 对施展的改写
      removeLimit?: string[];                     // 移除施展限制
      actionCost?: 'main' | 'bonus' | 'none';     // 改写动作消耗
      effectMultiplier?: number;                  // 效果倍率
    };
  };
  consumeOn: 'cast' | 'hit' | 'turn-end';         // 何时消耗
}
```

**这样三处缺口变成一处参数**：

| 技能 | 做法 |
| --- | --- |
| 潜行之刃 | 给自身施加状态「潜行之刃」，`consumeOn: cast`，`removeLimit: ['必须处于潜行状态']` |
| 毒性蔓延 C | 施加状态，`effectMultiplier: 2`，过滤「毒刃的中毒效果」 |
| 毒性蔓延 D | 施加状态，`actionCost: 'bonus'`，过滤「毒刃」 |

状态本身走 E03 已有生命周期（施加、叠层、时长、解除），只是多带一个 `payload` 字段。

## 2. 「唯一性」写明白

**定义（用户 2026-10-24）**：同一时间只能作用于单一单位；持续时间内再次施展同名技能，旧目标的效果立即取消并转移到新目标；同名的复数唯一性效果不叠加。

**在模型中的位置**：`cast.modifiers` 里的一项，不是引擎、也不是状态。

```ts
modifiers: [{ type: 'unique', key: 'skill-name' }]
```

执行语义：

| 时点 | 行为 |
| --- | --- |
| 施加前 | 按 `key` 查找场上同名唯一实例 |
| 存在旧实例 | 撤销旧实例，记录转移原因 |
| 施加后 | 注册 `key → 新实例`，旧的注销 |
| 同名多个效果 | 只保留最新一个，不叠加 |

关键点：`key` 用**技能名**而非技能 ID——原文说的是「同名技能」，不同来源的同名也算。

# 附：v2.1 修订（能力引用）

用户提示：「我们技能描述内关于其他能力的引用确实非常多」。核实后全库有 **34 条**技能以「关键词.能力名」形式引用其它能力。

## 1. 引用类型

```ts
interface AbilityRef {
  byKeyword?: string;   // '战技' | '法术' | '天赋' | '戏法' …
  byName: string;       // '毒刃' | '暗影之刃' | '快速备战'
  disambiguateBy?: { classOrDomain?: string; style?: string };  // 同名不同源时消歧
}
```

## 2. 解析与三态

| 状态 | 含义 | 处理 |
| --- | --- | --- |
| `resolved` | 唯一命中一条能力 | 记录稳定 ID 与解析依据 |
| `ambiguous` | 命中多条且无法消歧 | **进异常清单，人工指定**，不默认取第一条 |
| `unresolved` | 找不到 | 进异常清单；该步骤标记为「不可执行」但保留原文 |

另外需记录引用目标的后续状态：**已停用**（D17 停用占位）时，引用方进入 `dangling` 态，展示时标注「引用的能力已移除」。

## 3. 依赖图

- 导入时构建 `能力 → 引用目标` 有向图，用于检测**循环引用**（A 引用 B、B 引用 A）。
- 循环本身不一定非法（互相引用在规则里可能出现），但必须在导入报告里列出，由人判断。
- 删除/停用一条能力时，反查引用它的能力，逐条列出影响。

## 4. E19 支持区间表

混沌法术（术士起始）是 D100 按区间分段的效果表，不是等分枚举。因此 E19 增加：

```ts
{ engine: 'E19', params: { mode: 'rangeTable', dice: '1D100', ranges: [
  { from: 1, to: 1, effect: [...] },
  { from: 2, to: 5, effect: [...] },
  { from: 6, to: 10, effect: [...] }
] } }
```

`rangeTable` 与 `valueTable`、`effectBranch` 并列，共三种用法。

## 5. 对本期的影响

- 能力引用**不进 26 个引擎**，它是模型的一等字段（`AbilityRef`），所有引擎的 ref 类参数共用。
- 引用解析属于**导入管线**的一部分，解析不了就进异常清单（与 D16 一致：不静默处理）。

## 1. 新增引擎

### E30 修正器（能力引擎）

对某个数值施加条件性修正。四批复核里约一半的 ⚠ 由它解决。

```ts
{ engine: 'E30', params: {
    target: 'ac' | 'hit' | 'damage' | 'damageRoll' | 'check' | 'checkBonus'
          | 'saveDC' | 'critRate' | 'incomingDamage' | 'moveSpeed' | 'maxHp' | 'maxFatigue',
    op: 'add' | 'mul' | 'set' | 'advantage' | 'disadvantage' | 'autoSuccess',
    value: number | Expr,
    condition?: Expr,
    scope?: 'self' | 'target' | 'area',
    duration?: number    // 省略 = 即时；填值 = 持续修正
} }
```

覆盖：AC 加值（#39/#23）、伤害结算后加值（#14/#54）、暴击率加值（#64/#66）、命中与伤害的优劣势（#63/#68/#69）、检定加值（#37）、承伤减半（#52）、豁免 DC 加值（#71）、伤害倍率（#53 的 50%/100%）、移动速度（#02 潜行减半）。

### E31 幻象与感官（能力引擎）

生成**虚假的存在感**，实际作用由 DM 裁决。

```ts
{ engine: 'E31', params: { kind: 'sound' | 'sight' | 'presence' | 'text',
    area: { shape, radius }, instances: number*, descr: string, ephemeral: true } }
```

覆盖：#40 影哨术（声响 + 类人生物错觉、9 级可同时三个）、#27 迷幻手稿（文字仅指定角色可见）。

### E32 调度与延迟（子系统）

在未来的某个时点执行效果。

```ts
{ engine: 'E32', params: { delay: { type: 'turn-start' | 'round-end' | 'duration-end' | 'after-n-rounds',

```

覆盖：#60 本轮结束阶段二次回复、#58 12 级「下 X 名角色回合开始时再位移」、#49 轮末结算（与 E09 配合）、#53 解除时追加伤害。

### E33 资源转移与分配（能力引擎）

把 N 点资源分配给 M 个目标，可至负数。

```ts
{ engine: 'E33', params: { resource: enum, total: number*, distribution: 'free' | 'equal' | 'chosen',
    allowNegative: bool, selfPenaltyIfMax?: number* } }
```

覆盖：#33 销赃网络（5 点任意分配、自己最多则他人各 −1、可负）、#29 窃贼的交易（换点）。

# 附：v5 修订（战士验证轮 · 2026-10-25）

> 触发：战士 119 条按「机制最典型」标准验证模型。结论是**机制面扛住了，结构面暴露 6 处缺口**。
> 引擎总数不变（65），本次只修结构与参数；新增引擎 E69–E70 见下。

## 1. 【硬伤】伤害来源要能「跟随武器」

法师的伤害是技能自带的（火球术自带火焰 + 4D6），所以 `damageType` / `damageDice` 一直按「施法者」设计。
**但战士 26/40 条是「用手里这把武器打」**——类型来自剑（挥砍/穿刺），骰式来自剑的条目。模型此前从未考虑这种来源。

```ts
// E01
{
  damageSource: 'spell' | 'weapon',        // 新增：伤害来自技能还是武器
  damageType: string | '跟随武器',          // 新增哨兵值
  damageDice: string | '跟随武器',          // 新增哨兵值
}
```

解析时若为 `'跟随武器'`，由角色当前装备的武器决定；武器未装备时报错而不是静默取 0。

另外把 **33 种伤害类型**独立成枚举（D157），不再复用「元素属性 20 种」。

## 2. 【结构】E02 拆开「区域」与「目标集合」

「对相距不超过 6 米的至多四名角色各发起一次攻击」**不是一块区域**——四个目标可以互不相邻、隔着墙。
硬套 E02 等于把「选四个点」降级成「一片区域」，AOE 的「范围内全部生效」语义完全不成立。

```ts
// E02 增
shape: '方形' | '扇形N环' | '直线' | '多目标'
constraint?: { maxTargets?: number, maxDistance?: number, mustSee?: boolean }
```

## 3. 【结构】时机词表补齐「轮次」层

`EffectStep.when` 此前只有 `turn-start` / `turn-end`（**角色**回合），但 `E32.delay` 里已有 `round-end`。
同一模型两套词表，是隐患。统一为：

```
round-start | round-end | turn-start | turn-end | before-hit | after-hit | on-kill
```

## 4. 【结构】表达式层补聚合函数

D92 只允许常量 + 变量 + 四则运算，但实际技能需要：

| 需求 | 现状 | 需要 |
| --- | --- | --- |
| 「周围 4 米内存在两名友方」 | 无法表达 | `count(area, filter)` |
| 「军旗周围三名或以上」 | 无法表达 | `count() >= 3` |
| 「回复等量但不超过 15」 | 靠 clamp 打补丁 | `min(x, 15)` / `max()` |

```ts
count(area, filter)  min(a, b)  max(a, b)  clamp(x, lo, hi)
```

## 5. 【结构】代受伤害要区分「谁掉血」与「谁的受伤事件」

`E10.redirectTo` 只解决「谁掉血」，没解决「受到伤害事件记在谁头上」。
而多條被動（戰士 #041 #045 #055）全挂在「受到伤害后」这个事件上——
**改一个 redirectTo 会静默改掉三条被动。**

```ts
// E10 增
redirectTo?: TargetRef,              // 谁掉血（已有）
damageEventOwner?: 'redirector' | 'target' | 'both',  // 新增
```

## 6. 【结构】多段攻击要区分「复制」与「递进」

`E01.segments` 只有段数。法师的多段是「同参数复制 N 份」；战士的多段是**每段吃上一段的结果**
（#010/#011：每未命中一次，下一段加关键属性）。

```ts
segments?: number
segmentMode?: 'copy' | 'chain',        // 新增：copy=同参数复制，chain=每段依赖上一段
perSegment?: Partial<E01Params>,       // 新增：逐段修正
```

## 7. 两处口径钉死

| 项 | 结论 |
| --- | --- |
| ⚠ 的定义 | ⚠ = **执行器按现文得不出唯一结果**。A/B 类因有保守落值**一律不占 ⚠**；C/D 类若存在保守读法也不占，无法保守落值才占 |
| 纯被动 + 次数 | `action: 'none'` 允许携带 `cast.uses`，语义为「触发式限次」，不是「施展限次」 |
