# 模型 v3 修订清单（2026-10-24 · 四批复核汇总）

> 来源：4 个子代理对 83 条的逐条独立复核（A #01–20、B #21–40、C #41–60、D #61–83）。
> 结论：v2.1 只能干净表达 **9/83（11%）**。缺口归类后不是 74 个独立问题，而是 **7 类**。

## 一、最核心的一个发现：缺「修正器」

四批报告里最高频的缺口，本质是同一件事——**对某个数值施加条件性的加减乘**：

| 报到的缺口 | 实际是 |
| --- | --- |
| 防御等级 + 感知调整（#39） | 修正 AC |
| 伤害值在结算后 +10（#14） | 修正伤害 |
| 每层标记使暴击率 +1（#64） | 修正暴击率 |
| 命中检定具劣势 / 优势（多处） | 修正检定 |
| 伤害值具有优势（#63/#68/#69） | 修正伤害掷骰 |
| 灵巧动作掷骰 + 偷窃熟练度（#37） | 修正检定结果 |
| 受 AOE 伤害结算后减半（#52） | 修正承伤 |
| 对灼烧/中毒豁免难度 +2（#71） | 修正豁免 DC |
| 命中与伤害本轮减半（#10） | 修正命中与伤害 |

**建议新增 `E30 修正器`**，作为一等引擎：

```ts
{ engine: 'E30', params: {
    target: 'ac' | 'hit' | 'damage' | 'damageRoll' | 'check' | 'saveDC' | 'critRate' | 'incomingDamage'
    op: 'add' | 'mul' | 'advantage' | 'disadvantage' | 'set'
    value: number | Expr
    condition?: Expr
    duration?: number
} }
```

这一条能吃掉四批报告里大约**一半**的 ⚠。
