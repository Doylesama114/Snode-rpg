## 3. 阶段计划

### P0 · 模型试点（10 条）

- **做什么**：用《技能效果步骤模型规范》拆 10 条，覆盖九类结构：纯攻击（背刺/影袭）、多变量参数（割裂）、分支（毒性蔓延）、随机（杂耍打击）、召唤（幻影匕首）、附魔改写（暗影之刃）、持续区域（旋刃魂曲）、状态赋予+行动禁止（无处可逃）、条件豁免（潜行之刃）。
- **交付**：10 份步骤序列 + 模型缺口清单。
- **验收**：10 条全部能写成合法步骤序列；若某条写不出，明确记录缺哪个引擎、哪个参数、哪个时机。
- **判断点**：缺口 >3 处则先改模型再继续，不进入 P1。

### P1 · 游荡者全量拆分（83 条）

- **做什么**：按试点确定的模型拆完 83 条。
- **交付**：83 份步骤序列 + **表达式覆盖率报告**（多少条需要表达式、用到哪些变量、出现频次）。
- **验收**：83 条全部有步骤序列；表达不了的逐条列明原因；覆盖率报告能回答「表达式能力够不够」。

### P2 · 引擎实现验证（游荡者）

- **做什么**：挑 5–8 个引擎做最小实现，用 83 条里的代表性技能跑纸面推演。
- **交付**：可运行的引擎骨架 + 推演记录。
- **验收**：至少 3 条技能能被真实执行，结果与规则参考一致。
- **依赖**：P1 完成。

### P3 · 其余 17 职业 + 6 领域

- **顺序**：法师（143 组合）→ 武僧 → 魔契师 → 奇械师 → 萨满 → 吟游诗人 → 德鲁伊 → 战士 → 游荡者已完成 → 其余按难度递降。
- **交付**：每职业一份步骤序列 + 新增引擎申请单。
- **验收**：每个职业技能全部分解；新增引擎逐个说明为何不能参数化。
- **判断点**：若某职业出现 3 个以上新引擎，暂停并复盘模型是否需要扩展。

### P4 · C 线：资料库结构与词条分类

- **做什么**：把模型落成数据库结构；实现 D60 的词条分类（官方 7 类关键词）。
- **交付**：表结构 + 词条分类数据 + 游荡者可完整入库并检索。
- **验收**：83 条能按职业/风格/阶位/形态/词条五个维度正确检索。
- **依赖**：P1 完成（步骤序列就是入库内容）。

- **依赖**：B 线数据补齐完成（否则资料库不完整）。
