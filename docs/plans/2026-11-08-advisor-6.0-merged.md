## 3. 目标

| 维度 | 目标 | 验收 |
|---|---|---|
| 可溯源 | 正文每个数字/名称可指回 `[E#]`，引用可点击 | 引用有效率 100%（行内 + 末行） |

## 4. 架构（六层，落地时按层独立上线）

```
在线：
 ① 路由      routes.json（12 族）→ 分类器兜底
 ② 实体解析  resolveEntity() 单一入口（职业/进阶/技能/装备/状态/专长）
             ★ 澄清闸门改为「解析之后」，只对解析不出的缺口追问
 ③ 检索      别名/口语映射 → BM25(字面+二元组) → 可选向量 → RRF 融合 → 重排
             ★ 规则层用新语料（lab 116 节 + 104 关键词）；技能层用职业页数据重建
 ④ 装配      稳定前缀（族固定提示 + 静态规则）→ 证据块 [E#]（变化）→ 用户问题
             预算：轻族 4k / 中族 5k / 重族 7k token；强相关放首尾
 ⑤ 生成      DeepSeek 流式 / 非流式；按族契约出章节
 ⑥ 校验      结构契约 → 数字落地 → 引用有效；失败补证据重试一次，仍失败降级并标注

离线：
 A 切块  技能/规则/装备/世界观 → 带语境头 chunk（职业·阶位·风格·来源·锚点）
 B 索引  BM25 倒排 + 别名表（+ 可选向量）；manifest 记 sha256 与条目数
 C 用例  反馈 → 12 族分层用例（200 条，带 capability 标签与金标）
 D 发布  L1 每次 / L2 发版前 / L3 每周抽样
```

### 5.1 修正（2026-11-08 实测）

lab 的 `rule-sections.json` **只有标题/目录，没有正文**（`body` 长度 7–18 字，`parts` 也是标题行），不能直接当规则语料。实际管线改为：

| 内容 | 来源 | 产物 |
|---|---|---|
| 规则正文 | **`斯诺德跑团/help.html`**（12 章，按 h3 切 + 长块按段切分） | 60 条 section chunk |
| 关键词定义 | help.html 的 `#s8` 表格 | 102 条 keyword chunk |
| 等级/兼职/幕间/色彩/状态/名望 | lab `rule-*.json`（事实表） | 126 条 fact chunk |
| 合计 | | **288 条**（`advisor/rules/chunks.jsonl`） |

检索：`scripts/advisor-search-prose.mjs`（BM25 + 标题加权 + 章节路由 + 停用词 + 覆盖率），零依赖。

实测（2026-11-08）：问「检定规则」→ 正确答出 D12/D8、难度六档；prompt 2,762 token（原 10,374），总耗时 4.8 s；44 条 eval 仍 43/44。

## 9. 风险

| 风险 | 对策 |
|---|---|
| 一次改两层（路由 + 检索）无法定位 | 每阶段只换一层；旧正则保留一版做 fallback |
| lab 快照缺 11.04 | 只作规则语料；技能与职业内容从 `源文件/` + `职业页/数据` 重建 |
| 校验误杀 | 先 warn 一周统计误报，再开 block |
| 工具循环拖慢 | 仅复合问句进循环，超时降级快路径 |
| 语料与规则书不一致 | 生成器输出「lab 章节 ↔ help.html 标题」对照表，不一致告警 |
