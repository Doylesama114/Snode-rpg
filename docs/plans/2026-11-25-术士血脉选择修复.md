# 术士「自身血脉」无法选择 — 修复计划（2026-11-25）

- 状态：待执行（未改代码）
- 现象：角色创建页选择术士后，「魔力血脉 → 伤害类型」能显示但点不动；即使点了，存档里也没有该值

## 1. 复现（已用 Playwright 验证）

1. 打开 `斯诺德跑团/角色创建页.html`，第 1 步选择「术士」；
2. 页面出现「魔力血脉 / 请选择一项伤害类型 / 奥术·火焰·冰霜·雷电·暗影·自然」；
3. 点击「火焰」→ 无选中态，`CHAR.specOpts` 仍为 `null`，下一步按钮仍可点。

## 2. 根因（四处，缺一不可）

| # | 位置 | 问题 |
| --- | --- | --- |
| 1 | `角色创建页.html` `renderSpecChoices()` 的 `area.onclick` | 只处理 `weapon-spec-btn` / `spec-attr` / `spec-skill`，**没有 `[data-field]` 分支**；`pickSpecOpt()` 形同虚设（只绑在背景熟练区，那里没有这类芯片） |
| 2 | `checkSpecDone()` | 只校验 `specChoices`，不看 `specOpts` → 术士可以不选血脉直接下一步 |
| 3 | `buildCreationSnapshot()` 与 `classChoices`（约 L601 / L3748） | 只存 `specChoices`，**不存 `specOpts`** → 草稿与最终存档都丢 |
| 4 | `panel_engine.js` 起始特性渲染（约 L1981–1997） | 有战士/法师/牧师/魔契师分支，**没有术士「魔力血脉」、猎人「自然探索」、萨满「元素亲和」** → 面板不显示 |

## 3. 影响面（同一机制共三类）

| 职业 | 特性 | 字段 | 现状 |
| --- | --- | --- | --- |
| 术士 | 魔力血脉 | `bloodline` | 点不动 + 不落库 + 不显示 |
| 猎人 | 自然探索 | `terrain` | 同上 |
| 萨满祭司 | 元素亲和 | `element` | 同上 |

| 环节 | 是否受影响 |
| --- | --- |
| 建卡草稿（自动保存/恢复） | 是：`buildCreationSnapshot` 不含 specOpts |
| 最终存档 `char_*_slot1` | 是：`classChoices` 不含 specOpts |
| 角色面板显示 | 是：无对应分支 |
| 导出 xlsx / 导入回读 | 跟随 `classChoices`，需回归验证 |
| Electron 镜像 | 是：需同步 |
| 旧存档 | 无该字段 → 显示「未选择」，不能报错 |

## 4. 修复方案

### 4.1 交互（`角色创建页.html`）

- 在 `area.onclick` 增加分支：`data-field` + `data-val` → 调用 `pickSpecOpt`；
- `pickSpecOpt` 补 `checkSpecDone()`，并给芯片加 `selected`；
- `checkSpecDone()` 增加：对 `SPEC_OPT_CHOICES` 中每个特性，若职业匹配且未选 → `allDone=false`（下一步禁用）；
- 未选时给出提示文案：术士「请选择魔力血脉的伤害类型」。

### 4.2 数据契约

```
classChoices = {
  weaponSpec, weaponSpecBonus,
  specChoices: {...},        // 既有
  specOpts: { bloodline: "火焰", terrain: "极地", element: "冰霜" }   // 新增
}
```

- `buildCreationSnapshot()` 增加 `specOpts`，恢复草稿时回填 `CHAR.specOpts`；
- 最终 `classChoices` 写入 `specOpts`；
- 旧存档无字段 → 读为 `{}`，面板显示「未选择」，建卡流程不阻塞。

### 4.3 面板（`panel_engine.js`）

- 起始特性渲染增加三个分支：
  - 术士 `魔力血脉` → 「伤害类型：火焰」；
  - 猎人 `自然探索` → 「地形：极地」；
  - 萨满 `元素亲和` → 「元素：冰霜」；
- 未选择 → 显示「未选择（建议重新建卡或等待编辑入口）」。

### 4.4 导出/导入与镜像

- 确认 `character_export` 走 `classChoices` 整体序列化（预期无需改）；
- `character_io` 导入回读 `specOpts`，缺省不报错；
- 同步 `electron-app/斯诺德跑团/角色创建页.html`、`panel_engine.js`（`sync-check` 必须通过）。

## 7. 风险

- 强制选择会让旧流程「下一步」从可用变禁用 → 需确认没有其它职业被误伤（只对三类职业生效）；
- 老草稿没有 `specOpts`，恢复后要提示补选，不能静默卡住；
- 面板新增分支避免影响既有特性描述（只追加，不改原 desc）。

## 8. 明确不做

- 不改血脉与伤害计算的联动（当前规则未要求自动改伤害）。
