# 技能效果 JSON 编写规范 v1.0

## ⚠️ 工作前置：对照 docx 修正技能描述

**在写 JSON 之前，必须先逐项对比 HTML 与 docx 原文件，修正所有不一致的字段。**

### 检查清单（每个技能过一遍，缺一不可）

| # | 检查项 | 对比方式 |
|---|--------|---------|
| 1 | **技能名** | HTML `<h4>` vs docx 技能标题是否一致 |
| 2 | **施展时间** | HTML `<span class="field">施展时间：</span>` vs docx |
| 3 | **施展距离** | 同上 |
| 4 | **持续时间** | 同上 |
| 5 | **疲劳消耗** | 同上 |
| 6 | **关键词** | 同上 |
| 7 | **前置条件** | 同上 |
| 8 | **额外条件** | 同上 |
| 9 | **施展条件** | 同上 |
| 10 | **施展限制** | 同上 |
| 11 | **费用（技能点颜色+数量）** | ⚠️ **重点检查** — 见下方 |
| 12 | **描述文本** | HTML `<p>` 文本 vs docx，逐段对比 |
| 13 | **等级升级描述** | `<span class="field">你的X级时：</span>` vs docx |
| 14 | **段落是否污染** | 描述末尾是否混入了下一个 section/skill 的文本 |
| 15 | **重复技能名** | detail div 内是否有多余的 `<p>技能名</p>` |

### 🚨 技能点颜色检查（重点）

**不仅是费用行，描述文本里嵌入的技能点也经常出错。** 比如：

```html
<!-- 费用行 -->
<p><span class="field">费用：</span><span style="color:#FF0000">●</span><span style="color:#EE822F">●</span></p>

<!-- 描述内的升级效果——也要检查！ -->
<p>获得技能点<span style="color:#FFF32F">●</span><span style="color:#00FA99">●</span></p>
```

**检查方法**：
1. 搜索 HTML 中所有 `skill_effects_schema.md` 外的 `<span style="font-size:1.5em;color:...">●</span>` 
2. 逐个对照 docx 中的费用符号（`●` / `●●` / `●●●` 等）
3. **颜色必须完全一致**：docx 字体颜色 → HTML `color:#XXXXXX`
4. 描述段落内嵌入的技能点颜色同样要检查（比如"获得技能点●●●"）

**颜色对照表**：

| 中文名 | 色值 | docx 字体色 |
|--------|------|------------|
| 红色 | `#FF0000` | FF0000 |
| 橙色 | `#EE822F` | EE822F |
| 黄色 | `#FFF32F` | FFD966 |
| 绿色 | `#00FA99` | 00B050 |
| 青色 | `#00B0F0` | 00B0F0 |
| 蓝色 | `#B3F9FF` | 00A0FF |
| 紫色 | `#B94BFF` | B94BFF |
| 粉色 | `#FFB7E3` | FF66CC |
| 棕色 | `#843F0B` | 843F0B |
| 白色 | `#FFFFFF` | FFFFFF |
| 黑色 | `#595959` | 595959 |
| 无色 | `#D9D9D9` | D9D9D9 |
| 浅色 | `#B3F9FF` | B3F9FF |
| 炫彩 | `linear-gradient` | 渐变 |

> ⚠️ docx 中的黄色是 `#FFD966`，但 HTML 用了 `#FFF32F`——这个差异是历史遗留，需逐项确认。

### 检查流程

1. 用 Python 提取 docx 段落（`python -c "import zipfile..."` 读取 `word/document.xml`）
2. 找到对应技能标题，向后读取 20-30 段获取完整字段和描述
3. 打开 HTML 找到对应 `<article id="...">`，对比每个字段
4. 如有不一致 → 用 `edit` 工具修正
5. Playwright 验证：`await page.locator('#skill-id .detail p').all_text_contents()` 确认修改生效
6. `git commit` + `git push`（不发版）

## 文件位置
`斯诺德跑团/skill_effects_{职业名}.json`

每个职业一个独立文件，按需加载。例如：
- `skill_effects_战士.json`
- `skill_effects_法师.json`
- `skill_effects_萨满祭司.json`

## 顶层结构
```json
{
  "战士": [
    { "id": "w-starting-skill-1", "name": "猛击", ... },
    ...
  ],
  "萨满祭司": [ ... ],
  ...
}
```
按职业名分组，每职业一个数组。技能 `id` 对应 HTML 中 `<article id="...">` 的值。

## 单个技能 Schema

### 必填字段

| 字段 | 类型 | 说明 | 示例 |
|------|------|------|------|
| `id` | string | HTML 对应 article id | `"w-starting-skill-1"` |
| `name` | string | 技能名 | `"猛击"` |
| `class` | string | 所属职业 | `"战士"` |
| `style` | string | 所属风格 | `"斗争风格"` |
| `tier` | string | 阶位 | `"一阶天赋树"` |
| `type` | string | 技能类型 | `"战技"` / `"法术"` / `"天赋"` / `"功法"` |
| `tags` | string[] | 关键词标签 | `["近战攻击","位移"]` |
| `cost` | object | 消耗 | 见下方 |
| `cast` | object | 施展参数 | 见下方 |
| `effects` | string[] | 效果描述（自然语言） | 见下方 |

### 可选字段

| 字段 | 类型 | 说明 | 示例 |
|------|------|------|------|
| `prerequisite` | string | 前置条件 | `"你拥有威力熟练度"` |
| `extra_condition` | string | 额外条件 | `"本次游玩中击退过敌人"` |
| `requirement` | string | 施展条件 | `"必须持有盾牌"` |
| `restriction` | string | 施展限制 | `"不能对2米内角色施展"` |
| `choices_from` | string | 抉择组标记 | `"抉择·选择其中两项习得：寒冰箭/火焰箭/雷光箭/强酸箭"` |
| `upgrades` | object[] | 等级升级 | 见下方 |

### `choices_from` 字段

当技能是抉择组（N选M）的一部分时使用。所有同组技能共享相同的 `choices_from` 值，方便 AI 识别互斥/共存关系。

```json
{
  "choices_from": "抉择·选择其中两项习得：寒冰箭/火焰箭/雷光箭/强酸箭"
}
```

---

### `cost` 对象

```json
{
  "fp": 1,              // 疲劳消耗，- 表示不消耗
  "sp": ["红", "蓝"],    // 技能点颜色数组，天赋/功法类型可省略
  "qi": 2               // 真气消耗（仅武僧），可选
}
```

### `cast` 对象

```json
{
  "time": "1动作",       // 0动作/1动作/2动作/附赠动作/主要动作/反应动作/1分钟/-
  "range": "近战",        // 自身/近战/触及/X米/远程/12米
  "duration": "立即"      // 立即/1轮/2轮/1分钟/1小时/-
}
```

**范围定义**：
- `近战` = 紧贴相邻
- `近程` = 4米
- `中程` = 6米
- `远程` = 12米
- `X米` = 动态距离，需在效果中说明公式

---

### `effects` 数组

**核心原则**：effects 用精炼的自然语言，让 LLM 能理解，不做过度结构化。

每条 effect 一行，格式：
```
{条件前缀}效果描述
```

**条件前缀**：
| 前缀 | 含义 |
|------|------|
| `造成 XdY {类型}伤害` | 伤害骰 |
| `附加 N × {属性}调整值` | 属性加伤 |
| `命中检定 +N` | 命中加成 |
| `完全免疫一次{类型}伤害` | 免伤 |
| `使目标进入{状态}` | 状态赋予 |
| `消耗 N 点真气` | 真气消耗 |
| `在 {条件} 后可追加一次攻击` | 连锁攻击 |
| `改为 {新值}` | 替换型升级 |
| `{条件}具有优势（2D20取高）` | 命中/伤害/属性检定优势 |
| `{条件}具有劣势（2D20取低）` | 劣势 |
| `极大优势（3D20取最高）` | 三骰取高 |
| `极大劣势（3D20取最低）` | 三骰取低 |
| `必定暴击（全部加总伤害×2）` | 100%触发暴击 |
| `自动替换为{新技能}` | 等级到达后旧技能消失，新技能自动获得 |
| `不消耗动作` | 不占主要动作/附赠动作，在自己的回合内自由使用 |
| `DC{N} {属性}豁免` | 标准豁免检定，d20 + 属性调整值 vs DC |
| `DC{N} 护甲检定` | 护甲检定，d20 + 护甲等级 vs DC（见下方） |

### 豁免与检定类型

| 类型 | 掷骰 | 加值 | 用途 |
|------|------|------|------|
| 属性豁免 | d20 | 对应属性调整值 + 熟练（如有） | 抵抗法术/状态效果 |
| 护甲检定 | d20 | 护甲等级（护甲 + 盾牌 + 敏捷） | 抵抗侵蚀/破甲效果 |
| 技能熟练检定 | d20 | 对应属性 + 熟练（如有） | 预知梦等天赋触发 |

### 优势/劣势体系

| 术语 | 含义 | JSON 写法 |
|------|------|----------|
| 优势 | 掷2个D20取高 | `"命中检定具有优势（2D20取高）"` |
| 劣势 | 掷2个D20取低 | `"具有劣势（2D20取低）"` |
| 极大优势 | 掷3个D20取最高 | `"极大优势（3D20取最高）"` |
| 极大劣势 | 掷3个D20取最低 | `"极大劣势（3D20取最低）"` |
| 伤害优势 | 掷2次伤害骰取高 | `"伤害值具有优势（2×伤害骰取高）"` |

> ⚠️ 优势/劣势 与 固定加值 是两个不同机制。
> `"命中检定+2"` 是固定加值，`"命中检定具有优势（2D20取高）"` 是优势。不要混用。

### 暴击体系

| 术语 | 含义 |
|------|------|
| 基础暴击 | 自然20触发，全部加总伤害×2 |
| 暴击范围+N | 暴击范围从20扩大到20-N |
| 暴击率+N | 等同于暴击范围+N |
| 必定暴击 | 100%触发暴击，伤害×2 |

### 终结技

| 术语 | 含义 |
|------|------|
| 终结技 | 需要至少2种可用反应动作才能抵挡，并消耗其中一种 |

### 优先级关键词

| 术语 | 含义 |
|------|------|
| 速攻 | 优先级高于反应动作和回合外能力，先结算速攻再结算其他效果 |
| 精锐 | 优先级高于低阶速攻/反应/回合外能力，但低于同位阶或高阶能力 |

**示例**：
```json
"effects": [
  "造成武器基础伤害（物理）",
  "附加 1 × 力量调整值",
  "L12: 附加改为 2 × 力量调整值"
]
```

---

### `upgrades` 数组（可选）

当技能在特定等级有数值变化时：

```json
"upgrades": [
  { "level": 5, "change": "施展时间变为附赠动作" },
  { "level": 8, "change": "关键词变为短休/长休（2）" }
]
```

**注意**：纯数值变化的升级（如 `命中+3`）写在 effects 里用 `L4: xxx` 标记；功能性变化的升级（如"施展时间改变"、"新增效果"）写在 upgrades 里。

## 完整示例（猛击）

```json
{
  "id": "w-starting-skill-1",
  "name": "猛击",
  "class": "战士",
  "style": "斗争风格",
  "tier": "一阶天赋树",
  "type": "战技",
  "tags": ["近战攻击"],
  "cost": { "fp": 1 },
  "cast": { "time": "1动作", "range": "近战", "duration": "立即" },
  "effects": [
    "造成武器基础伤害（物理）",
    "附加 1 × 力量调整值",
    "L12: 附加改为 2 × 力量调整值"
  ]
}
```

## 编写注意事项

1. **effects 不要过度结构化**。`"附加 1 × 力量调整值"` 比 `{"type":"bonus","source":"str_mod","count":1}` 更好——LLM 能理解前者，后者需要 schema 文档。
2. **数值 + 单位不可省略**。`"造成 1D6 点雷电伤害"` 而非 `"造成雷电伤害"`。
3. **升级用 `L{等级}: ` 前缀标记**。挂在 effects 或单独 upgrades 数组。
4. **tags 要全**。关键词标签是小助手检索匹配的主要依据。
5. **id 必须与 HTML article id 一致**。方便前端绑定。
6. **范围用中文标准**：近战/近程/中程/远程/X米。

## 附：异常状态与反应动作

编写涉及反应动作的技能时，以下状态会**阻止反应动作**（参见帮助页 §7）：

| 类别 | 状态 | 阻止原因 |
|------|------|---------|
| 失能 | 瘫痪/震撼/冻结/眩晕/击晕 | "持续时间内无法执行任何动作" |
| 限制 | 麻痹 | 明确"无法响应反应动作" |
| 限制 | 魅惑 | 明确"期间无法执行反应动作" |
| 限制 | 忏悔 | "对外界熟视无睹" |
| 限制 | 昏睡 | "陷入沉睡中，对外界熟视无睹" |
| 限制 | 缴械 | 失去手持物件（含盾牌/武器） |
| 限制 | 恐惧(D6) | "跳过下一个自身回合" |
| 限制 | 混乱(D2-5) | "跳过下一个自身回合" |

**部分阻止反应动作**（条件性）：
| 状态 | 阻止范围 | 不阻止范围 |
|------|---------|-----------|
| 击倒 | 含**位移**关键词的反应动作 | 其他反应动作（如盾牌格挡） |
| 压制 | 含**位移/空中**关键词的反应动作 | 其他反应动作（如盾牌格挡） |
| 沉默 | **法术**类反应动作（不会腹语） | 战技/功法类反应动作（如盾牌格挡） |

**不阻止反应动作**：
灼烧、中毒、流血、霜冻、减速、禁锢、致盲、耳鸣、困惑、恐惧(D1-5)、混乱(D1/D6)、醉酒
